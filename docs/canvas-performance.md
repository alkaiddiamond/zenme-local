# 画布性能基线与回归

画布性能优化遵循一个稳定约束：移动视口期间，节点外层保持挂载，主线程热路径只处理 viewport transform。持久状态、临时交互状态和渲染工作集必须相互独立。

## 基准场景

打包应用基准使用 Chrome DevTools Protocol 驱动真实 Electron 渲染进程，固定执行平移、缩放、节点拖拽、resize、连线和框选，并记录真实 `requestAnimationFrame` 间隔、长任务、React 根提交、节点挂载、布局、脚本和 JS heap。

| Profile | 节点 | 边 | 用途 |
| --- | ---: | ---: | --- |
| `daily` | 100 | 150 | 日常回归 |
| `large` | 500 | 750 | 合并门禁 |
| `pressure` | 1,000 | 2,000 | 压力与容量观察 |

运行方式：

```powershell
npm run desktop:pack
npm run desktop:perf:assert
npm run desktop:perf
```

`desktop:perf:assert` 对 `large` 场景执行门禁。报告写入 `.logs/canvas-performance-latest.json`，这是动态产物，不提交仓库。基准为隐藏窗口关闭 Chromium 后台节流，避免被窗口遮挡状态污染结果。

## 验收阈值

- 500 节点各交互 P95 不超过 17.0ms。
- 不允许出现 50ms 以上的主线程长任务。
- 不允许交互期间发生节点 mount/unmount。
- 平移和缩放只允许开始、结束边界的少量根提交。
- 30 秒静置后的 heap 不应持续增长。

60Hz 理论帧预算是 16.67ms；浏览器时间戳量化后稳定帧会报告为 16.7–16.8ms，因此自动门禁使用 17.0ms，避免把正常量化误判为回退。

## 2026-08-07 Windows 基线

Windows x64 打包应用的 `large` 场景结果：

| 交互 | P95 | 长任务 | CanvasClient commits | 节点挂载变化 |
| --- | ---: | ---: | ---: | ---: |
| 平移 | 16.8ms | 0 | 2 | 0 |
| 缩放 | 16.8ms | 0 | 2 | 0 |
| 节点拖拽 | 16.7ms | 0 | 4 | 0 |
| resize | 16.7ms | 0 | 2 | 0 |
| 连线 | 16.8ms | 0 | 1 | 0 |
| 框选 | 16.7ms | 0 | 2 | 0 |

500 个节点外层全部常驻；20 个视口周边节点启用完整重型内容，其余节点保留稳定外壳。750 条边完整保留在持久数据和历史中，React Flow 渲染层当前使用 50 条与活动节点相关的边。30 秒内存观察为 `-0.89MB`，没有持续增长。

`pressure` 场景最终运行中，平移、缩放、resize 和框选 P95 为 16.7–16.8ms，30 秒 heap 为 `-48.91MB`；节点拖拽 P95 为 33.3ms，完成连线时有一次 77ms 长任务。它不影响 500 节点合并门禁，但作为下一阶段容量优化项保留，不能据此宣称 1,000 节点已经达到同一帧预算和长任务目标。

## 当前实现边界

- `onMove` 只更新 viewport ref 和采样，`onMoveEnd` 才提交外层状态和刷新工作集。
- Ctrl/Meta 滚轮输入按动画帧合并，停止输入后提交最终 viewport。
- 节点拖拽和 resize 的逐帧预览直接进入 React Flow store，持久节点只在释放时合并一次。
- 节点坐标变化不重建边派生；密集画布只向渲染层提供活动节点相关的边工作集。
- 重型节点采用“完整内容 + 稳定外壳”，不会因刚离开视口就卸载整个节点。
- 自动保存和缩略图在交互期间暂停；保存队列合并到最新请求，缩略图只克隆视口附近 DOM。
- 音乐播放 actions、低频 status 和高频 session 使用独立订阅；播放时间不会让画布根组件重渲染。

目前没有把快照清洗和 JSON 序列化迁移到 Worker。500 节点实测快照构建和签名通常约 `0.1–1.5ms`，没有形成长任务；此时引入 Worker 会增加结构化克隆、生命周期和失败恢复成本。若压力基准中该指标接近帧预算，再以运行数据触发迁移。

## 回归排查

出现回退时先查看报告中的：

1. `p95Ms` 与 `longTaskMaxMs`，区分持续掉帧和单次长任务。
2. `canvasCommits`，确认高频状态是否进入画布根组件。
3. `nodeMounts` / `nodeUnmounts`，确认是否引入视口挂载抖动。
4. `canvasMetrics`，定位签名、节点派生、边派生、历史或缩略图成本。
5. `layoutMs`、`scriptMs` 和 DOM 中完整内容/外壳/边数量，判断瓶颈属于 React、布局还是工作集规模。

性能修复必须先用固定场景复现，再增加相应回归断言；不要仅凭开发模式手感调整阈值。
