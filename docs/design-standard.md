# Zenme 视觉与交互设计标准

本文档是 Zenme Local 视觉和交互实现的唯一权威标准。`docs/prd.md` 记录产品能力与业务规则；本文件规定这些能力在界面中的呈现和操作方式。代码与本文冲突时，应修正代码或先更新本文，不能让未记录的临时样式成为新惯例。

## 1. 设计目标

- 产品是桌面工作台，第一屏直接进入可操作界面，不做营销式首页。
- 整体气质为冷灰白、安静、轻量、工具化，参考 cc-haha 的信息密度和克制层级。
- 视觉层级主要由间距、边框、文字色和少量字重构成，不依赖大色块、装饰渐变或夸张阴影。
- 高频操作应在一次点击内到达；控件出现与消失不能引起主内容跳动。
- 本地优先语义必须准确，不出现“云端保存”“同步到云端”等误导文案。

## 2. 设计令牌

令牌定义在 `app/globals.css`。业务组件优先使用令牌，画布组件允许通过统一语义类使用固定中性色，不在组件内创建新的色彩体系。

### 2.1 色彩

| 用途 | 令牌 | 当前值 |
| --- | --- | --- |
| 主背景 | `--color-surface` | `#ffffff` |
| 侧栏背景 | `--color-surface-sidebar` | `#f3f6fa` |
| 顶栏背景 | `--color-surface-topbar` | `#f8fafc` |
| 浅容器 | `--color-surface-container-low` | `#f7f9fc` |
| hover 容器 | `--color-surface-container-high` | `#edf1f6` |
| 主文字 | `--color-text-primary` | `#111827` |
| 次级文字 | `--color-text-secondary` | `#4b5563` |
| 弱文字 | `--color-text-tertiary` | `#8b95a5` |
| 默认边框 | `--color-border` | `#e3e8ef` |
| 强边框 | `--color-border-strong` | `#d5dce7` |
| 聚焦边框 | `--color-border-focus` | `#b6c0ce` |
| 品牌强调 | `--color-brand` | `#8f482f` |
| 运行按钮 | `--color-run` | `#ead5cf` |
| 错误 | `--color-danger` | `#dc2626` |
| 成功 | `--color-success` | `#15803d` |

使用规则：

- 默认按钮和导航项透明；hover 使用浅容器色。
- 品牌色仅用于 tab 激活线、少量选中强调和关键边框。
- 蓝色仅用于文本选择、链接和代码语法，不作为产品主色。
- 截图中的青色圆形是鼠标控件，不属于产品视觉元素。
- 禁止装饰性渐变、彩色光斑、背景圆球和大面积紫色、棕色或蓝色主题。
- 错误、警告、成功色只表达状态，不作为装饰。

### 2.2 字体和字重

- UI 正文：`--font-body`，Inter + 中文系统字体。
- UI 标题：`--font-headline`，Manrope + Inter + 中文系统字体。
- 代码：`--font-mono`，JetBrains Mono。
- UI 正文和普通标签使用 `400`。
- 当前项、按钮名称、节点标题和页面标题最多使用 `500`。
- UI 禁止 `600/700`；数字统计的主数值可以使用 `600`，但说明文字仍为 `400`。
- Markdown、EPUB、用户文档中的标题字重属于内容语义，不受 UI 字重限制。
- 不使用负字距；不按视口宽度缩放字号。

推荐字号：

| 场景 | 字号 |
| --- | --- |
| 页面标题 | `20px` |
| 区块标题 | `16px` |
| 正文、按钮、tab、节点内容 | `14px` |
| 节点标题、辅助标签、状态 | `12px` |
| 代码 | `13-14px` |

### 2.3 间距、圆角和阴影

- 基础间距单位为 `4px`；常用间距为 `8/12/16/24/32px`。
- 图标按钮固定为 `32px` 或 `36px`，同一工具栏不得混用。
- 普通按钮、输入框和菜单项圆角为 `8px`。
- 项目卡片和设置区块圆角不超过 `8px`。
- 画布节点和浮动编辑器属于 framed tool，统一使用 `12px` 圆角。
- 胶囊只用于工具栏、分段选择和状态标签，不用于普通命令按钮。
- 普通页面卡片不使用阴影；菜单使用下拉阴影；浮动工具使用画布阴影。
- 画布节点使用独立节点阴影，并保持原 `shadow-xl` 的明显悬浮效果；节点需要与无限画布形成清楚的纵深关系，不能为了“轻量”弱化为贴边阴影或不可见阴影。
- 禁止嵌套卡片阴影和多层装饰阴影。

阴影实现规则：

- 阴影统一由 `--shadow-node`、`--shadow-canvas`、`--shadow-dropdown` 和 `--shadow-overlay` 语义令牌定义。
- 组件必须使用 `zenme-shadow-node`、`zenme-shadow-canvas`、`zenme-shadow-dropdown` 或 `zenme-shadow-overlay` 语义类；这些类直接设置 `box-shadow: var(...)`。
- 禁止使用 `shadow-[var(--shadow-*)]`。当前 Tailwind 编译器会把这类任意值误判为 `--tw-shadow-color`，不会生成实际 `box-shadow`，界面最终会完全没有阴影。
- 新增阴影类型时，先增加全局令牌和对应语义类，再在组件中引用；不得在业务组件内散落自定义 `box-shadow` 或任意 Tailwind 阴影值。
- 验收时不能只检查源码类名，还必须检查编译 CSS 或浏览器计算样式，确认目标元素的 `box-shadow` 不为 `none`。

## 3. 应用框架

### 3.1 固定结构

- 展开侧栏宽 `280px`，收起侧栏宽 `48px`。
- 顶部 tab 栏高 `40px`，从侧栏右侧开始。
- 主内容从侧栏和 tab 栏之后开始，内部滚动条不得穿过顶栏。
- Electron 使用无框窗口；拖拽区域标记 `data-desktop-drag-region`，交互元素标记 `data-desktop-no-drag`。
- 页面和画布使用父容器高度，不使用裸 `100vh` 抢占窗口。

### 3.2 侧栏

内容顺序：展开按钮与品牌、新建项目、项目搜索、项目列表、首页、设置、本地模式。

- 所有侧栏命令默认透明，hover 才出现浅灰背景。
- 当前项不显示白色卡片，只使用文字色或 `500` 字重区分。
- 项目顺序稳定：点击、打开、保存都不能重排；置顶只改变置顶分组。
- 项目操作使用图标菜单，提供重命名、置顶/取消置顶等操作。
- 收起后只保留可识别图标，并提供 tooltip。

### 3.3 顶部 tab

- tab 保持打开顺序，切换不重排；新 tab 追加到末尾，最多 9 个。
- 当前 tab 只使用底部品牌色细线和 `500` 字重。
- 点击项目 tab 名称打开统一重命名弹层；不使用 inline 输入框。
- 关闭当前 tab 后切换到相邻 tab 或首页。
- tab 文字必须截断，不得挤压窗口控制按钮。

## 4. 页面与通用控件

### 4.1 页面布局

- 首页、项目列表和设置页采用无框的内容带，不把整个页面包进大卡片。
- 页面内容宽度和边距应响应窗口；设置弹窗上下至少保留 `80px` 安全边距。
- 不使用超大 hero 标题；工作台页面首标题不超过 `20px`。

### 4.2 按钮

- 熟悉动作优先使用 Lucide 图标；陌生图标必须有 tooltip。
- 普通命令：透明或白底，hover 浅灰。
- 主提交：使用运行色或深色圆形发送按钮；同一上下文只出现一个主操作。
- 危险操作：默认中性，hover 或确认阶段变红。
- 禁用态保留布局和标签，降低对比度并禁止指针操作。
- 保存按钮在有未保存更改时必须清晰可见；保存成功后页面或弹窗保持打开并反馈状态。

### 4.3 输入与选择

- 输入框白底、1px 边框、8px 圆角；focus 使用聚焦边框或轻 ring。
- placeholder 使用弱文字色；输入文字 `400`。
- 二元设置使用开关或 checkbox；模式使用 segmented control；模型等选项使用菜单。
- 输入获得焦点必须显示插入光标；不可编辑画布区域必须隐藏插入光标。
- 模式切换、失焦和重新聚焦不得清空或改写用户输入。

### 4.4 弹层与菜单

- 下拉菜单宽度稳定、8-12px 圆角、白底、浅边框和单层阴影。
- 模态弹窗上下保留至少 `80px`，标题与底部操作固定，内容区独立滚动。
- Escape 关闭最上层弹层；点击遮罩可关闭预览，但有未保存表单时必须先确认。
- 保存不自动关闭编辑服务商等需要连续配置的弹窗。
- 不可恢复的删除操作必须使用二次确认弹窗，不得从菜单项直接执行。
- 删除确认弹窗必须显示具体对象名称、不可恢复说明、普通“取消”按钮和危险色确认按钮；确认按钮应写明对象，例如“删除项目”，不能只写“确定”。
- 删除执行期间禁用关闭、取消和确认按钮并显示进行中状态；失败时保留弹窗并在原位显示错误。

## 5. 无限画布

### 5.1 画布基础

- 画布根容器使用 `h-full`，工具不得覆盖内容边界。
- 缩放范围为 `20%-250%`；Ctrl + 滚轮在节点上方同样缩放画布。
- 顶部、侧边和底部工具栏保持屏幕物理尺寸，不随画布缩放。
- 双击空白画布打开添加菜单；双击输入区或节点控件不触发菜单。
- 粘贴文本创建文本节点，粘贴图片创建图片节点，复制节点后粘贴复制节点；粘贴不复制连线，也不自动选中新节点。

### 5.2 节点统一结构

节点由“标题行 + 8px 间距 + 主框”组成：

- 标题行高 `20px`，使用 `12px/500` 和弱文字色。
- 主框默认圆角 `12px`、1px 边框、白底和统一节点阴影。
- 文本和图片生成默认主框尺寸统一为 `520 × 260`。
- 主框尺寸不包含标题行；浮动工具和输入控件不参与节点尺寸计算。
- 节点最小尺寸必须固定，动态文案、加载态和 hover 控件不能改变布局。
- 用户调整过尺寸的节点保留用户尺寸；仅迁移已知历史默认尺寸。

### 5.3 节点状态

- 默认：浅边框，隐藏辅助控件。
- hover：显示可用的加号和内联操作，不改变尺寸。
- selected：主框使用深色 1px 边框；显示上方工具栏和下方输入控件。
- focus-within：等同 selected 的边框反馈，输入光标正常显示。
- renaming：只显示名称输入，隐藏工具栏、连接点、缩放柄和其他操作。
- dragging：全局隐藏节点浮动控件、内联控件、连接点和缩放柄。
- loading：保留旧结果，在主框内显示轻量加载状态；成功后原位替换。
- error：在下方输入控件内显示受控错误，不改变主框尺寸。

### 5.4 工具栏与输入控件

- 上方工具栏和下方输入控件均以主框水平中心对齐。
- 两者使用逆缩放保持合理物理尺寸，缩放画布时不能无限变大或缩小。
- 上方工具栏为白色胶囊、浅边框、统一阴影；图标按钮 `32/36px`。
- 文本与图片节点的下方 AI 输入控件为白色 framed tool，默认宽 `640px`、最小高 `220px`，最大不超过可视区域；与主框间距在屏幕空间保持 `12px`。
- 点击节点主区域即可选中，不要求点击标题；输入控件内部点击不得拖动节点。
- 模型、比例、清晰度等选择分别记住同模态上一次选择。

### 5.5 连接点

- 左侧为输入，右侧为输出；连接点相对实际主框垂直居中，标题行不参与中心计算。
- 无父节点时不显示左侧白点；有连线时持续显示。
- 右侧加号与输出端点同一水平线；加号打开“引用该节点生成”菜单。
- 图片连线连接到图片框中点，不连接到标题或下方输入控件。
- 连线使用三级状态：未选择关联节点时为淡色；任一端节点被选中时为中色；连线自身被选中或获得键盘焦点时为重色，且连线自身状态优先级最高。
- 三级连线均使用半透明中性灰，使多条连线交叉处可通过透明叠加辨认；不得使用接近纯黑的不透明选中色。线宽随状态小幅递增，点击热区应宽于可见线条。
- 拖动和重命名期间连接点隐藏。

### 5.6 文本节点

- 保留纯文本、Markdown、代码模式和格式工具；切换模式不得丢内容。
- 代码模式显示语言子选项；Markdown 预览和编辑共享同一份源内容。
- 选中后下方展开 AI 对话控件；提交后立即创建独立 AI 回复子节点，运行状态、计时、结果和错误均显示在子节点，不在输入控件内显示临时任务状态。
- 同一源节点的直属生成任务运行期间禁用提交按钮；失焦、重新选中或缩放画布不得丢失运行状态。任务完成后允许再次提交并创建新的并列子节点。
- 文本节点、阅读笔记等文本类节点使用相同对话交互。

### 5.7 图片节点

- 上传图和生成图使用真实宽高比，不裁切、不拉伸、不填黑边。
- 画布显示尺寸使用统一外接圆算法：以 `280 × 280` 的对角线为固定直径，任意宽高比内接于同一参考圆。
- 原图用于下载和后续处理；画布预览最长边 `1200px`、WebP 质量 `0.88`。
- 图片上方工具栏提供最大化和下载，样式与文本工具栏一致。
- 最大化预览显示原图、提示词、模型、质量和宽高比。

### 5.8 图片生成与参考图处理

- 双击画布可创建独立图片生成节点，不需要参考图。
- 产品界面只使用“图片生成”节点；从现有图片的操作入口创建时，通过连线将来源图片加入候选并默认选为参考。
- 图片生成输入控件顶部使用紧凑缩略图列展示用户已选参考图片；输入 `@` 或点击“+”打开已连接图片选择器，支持搜索、多选和取消；选择一张图片后立即关闭选择器。
- 参考选择器默认关闭；选中或重新选中图片生成节点时只展开 AI 输入控件，不得自动打开参考选择器。
- 已选参考标签最多显示 10 个 Unicode 字符，超出后显示 `...`，悬停仍可查看完整名称。无参考时保留“+”入口，悬停提示为“参考”。缩略图不得改变主节点尺寸或下方输入控件的屏幕尺度补偿。
- 图片生成和图片编辑是同一节点的两种任务语义，不得提供独立的图片编辑节点，也不得根据 URL 猜测任务类型。
- 历史数据兼容必须在持久化迁移层一次性完成；渲染组件不得保留旧节点类型分支或通过旧字段临时伪装新节点。
- 没有参考图时，以用户描述进行纯图片生成；存在参考图时，根据用户指令选择精确编辑或基于参考图重新生成。精确编辑应最大限度保持主体身份、结构、构图、光照和未指定区域。
- 每次生成都在源节点下游创建独立结果子节点；运行中先显示固定尺寸占位框，成功后只回填该占位节点。历史图片结果和源节点不得被后续请求覆盖。
- 图片直属结果运行期间禁用源节点生成按钮；计时与失败信息属于结果子节点，并随画布持久化。
- 图片生成节点共享最近一次图片选项偏好，包括模型、宽高比和画质；选项改变后立即记忆，新节点沿用，已有节点的独立配置不得被全局偏好覆盖。

### 5.9 阅读器节点

- 展开和最小化保持当前位置、页码、目录高亮和面板尺寸。
- 重新展开后目录滚动到当前项。
- 阅读正文属于用户内容，可保留出版物标题层级和字重。
- 阅读器内部滚动不得推动画布缩放；仅 Ctrl + 滚轮交给画布。

### 5.10 音乐工作流节点

- 音乐资产、播放器、歌词与结构、综合分析、Suno 提示词节点均遵循统一的“外置标题行 + 主框”结构；不得把节点名称仅放在主框内部。
- 所有音乐类节点标题使用 `EditableNodeTitle`，支持双击重命名；重命名时隐藏连接点、输出加号和其他操作控件。
- 音乐资产主框固定为 `360 × 112px`；播放器主框固定为 `520 × 320px`。任务进度、状态与单行错误使用预留区域，不得改变主框尺寸。
- 歌词与结构主框固定为 `460 × 560px`。综合分析主框默认尺寸为 `620 × 720px`、最小尺寸为 `480 × 420px`；Suno 提示词主框默认尺寸为 `520 × 360px`、最小尺寸为 `420 × 280px`。综合分析与 Suno 提示词节点均允许用户调整尺寸，调整后的尺寸随画布保存；长内容必须占用主框剩余高度并在主框内部滚动，不得越过节点边框。
- 歌词节点的歌词与结构分段占用主框剩余高度，滚动容器使用 `min-height: 0` 约束，不得越过主框底边；节点内部不重复展示“来自播放器”说明、定位图标或成功状态条。
- 播放器常规控制包括播放/暂停、进度、静音、音量、倍速和循环。分析、取消、重试及创建结果节点统一放入右侧拉线菜单，不在主框底部重复显示操作栏。
- 播放器不显示完整分析任务的进度、成功或错误状态。从播放器拉出的歌词、综合分析、Suno 等操作必须先在松开位置创建独立节点，再由该节点使用统一状态区展示排队、进度、取消、失败与重试。
- 分析结果节点的状态区在执行中同时显示阶段、进度和按秒更新的“已运行”时间；成功、失败或取消后改为“用时”，并保留最终总耗时。时间文字使用 `12px` 次级色，不采用大号倒计时或动画数字。
- 歌词节点的运行/最终耗时位于主框外侧右上角，与外置标题共用一行；仅显示紧凑时间值，单位采用 `s`、`m`、`h`，例如 `58s`、`1m 2s`，不得在歌词内容区占用一行。
- 歌词曲库匹配不使用专辑名或专辑版本作为身份依据；候选选择只比较标题、歌手与音频时长，专辑信息只允许作为只读元数据展示。
- 完成但带能力警告的任务使用浅警告底色并直接说明缺失能力，不继续显示“等待结果”；核心能力缺失应呈现为失败状态。
- 播放器只允许展示由真实音频计算得到的波形响度包络；连接音乐文件后立即在后台请求轻量波形任务，完成前显示生成状态，禁止使用随机、循环或固定数据模拟波形。
- 波形显示必须覆盖歌曲从开始到结束的完整时间范围。服务端按时间桶计算 RMS 包络并进行全曲稳健归一化；前端点数超过显示宽度时继续按 RMS 分桶，不得截取数组前段、只取瞬时最大值或把偶发瞬态扩散成大面积满幅柱。
- 播放器和综合分析节点必须复用同一波形降采样与归一化规则；波形算法版本变化时应使旧服务缓存和画布缓存失效并自动重新生成。
- 音乐类节点都使用 `NodeFrame` 和 `--shadow-node` 语义阴影；选中边框、输入/输出端点以及输出加号与其他画布节点保持一致。
- 音乐资产只允许创建或定位唯一播放器；播放器是歌词、综合分析和 Suno 提示词等结果节点的直接上游。

## 6. 反馈、文案和可访问性

- 保存状态只使用：`正在保存到本地`、`已保存到本地`、`本地保存失败`、`本地服务不可用`。
- 按钮使用短动词：`新建项目`、`重命名`、`置顶`、`保存`。
- 不在主界面写教程式说明；空状态只说明下一步动作。
- 图标按钮必须有 `title` 或可访问名称；键盘 focus 可见。
- 文本对比度不低于常规桌面工具要求；状态不能只靠颜色表达。
- 动画以 `120-220ms` 的 opacity、颜色和轻位移为主，不使用弹跳或持续装饰动画。

## 7. 品牌与资源

- 主 logo：`public/brand/zenme-logo.png`。
- 方形图标：`public/brand/icons/zenme-logo-{16,24,32,48,64,128,256,512,1024}.png`。
- 应用窗口和任务栏使用方形图标，不使用横向裁切图。
- 品牌名和 logo 只出现在应用框架，不重复出现在项目内容区。

## 8. 实现约束

- 新增颜色、阴影、尺寸先进入 token 或共享组件，再在业务组件使用。
- 优先复用 `NodeFrame`、节点工具栏、模型选择器、浮动菜单和统一输入控件。
- 不新增装饰渐变、嵌套卡片、无功能装饰或随意的 `font-semibold/font-bold`。
- 特殊样式必须在本文件记录适用范围；“现有页面如此”不是新增例外的理由。
- 每次 UI 修改至少运行 `npm run lint`、`npm test`、`npm run build`。

## 9. 一致性验收清单

提交 UI 改动前逐项确认：

1. 是否使用已有 token、字号、圆角和阴影？
2. 默认、hover、selected、focus、disabled、loading、error 是否完整？
3. 控件出现后是否引发布局跳动或文字溢出？
4. 画布缩放后，上下浮动控件是否保持合理物理尺寸并居中？
5. 节点连接点是否相对主框居中，拖动/重命名时是否隐藏？
6. 模式切换、失焦、重开页面是否保留用户内容和选择？
7. 是否存在无意义背景、渐变、过重阴影、粗体或大圆角？
8. 文案是否符合本地优先语义？
9. 键盘、tooltip、focus 和 Escape 行为是否可用？
10. 桌面窗口、窄窗口和不同画布缩放下是否无重叠和遮挡？
