# Zenme 视觉与交互设计标准

本文档是 Zenme Local 视觉和交互实现的唯一权威标准。`docs/prd.md` 记录产品能力与业务规则；本文件规定这些能力在界面中的呈现和操作方式。代码与本文冲突时，应修正代码或先更新本文，不能让未记录的临时样式成为新惯例。

## 1. 设计目标

- 产品是桌面工作台，第一屏直接进入可操作界面，不做营销式首页。
- 整体气质为冷灰白、安静、轻量、工具化，参考 cc-haha 的信息密度和克制层级。
- 视觉层级主要由间距、边框、文字色和少量字重构成，不依赖大色块、装饰渐变或夸张阴影。
- 高频操作应在一次点击内到达；控件出现与消失不能引起主内容跳动。
- 本地优先语义必须准确，不出现“云端保存”“同步到云端”等误导文案。

## 2. 设计令牌

令牌定义在 `app/globals.css`。业务组件优先使用令牌，画布组件允许通过统一语义类使用固定中性色，不在组件内创建新的色彩体系。

### 2.1 色彩

| 用途 | 令牌 | 当前值 |
| --- | --- | --- |
| 主背景 | `--color-surface` | `#ffffff` |
| 侧栏背景 | `--color-surface-sidebar` | `#f3f6fa` |
| 顶栏背景 | `--color-surface-topbar` | `#f8fafc` |
| 浅容器 | `--color-surface-container-low` | `#f7f9fc` |
| hover 容器 | `--color-surface-container-high` | `#edf1f6` |
| 主文字 | `--color-text-primary` | `#111827` |
| 次级文字 | `--color-text-secondary` | `#4b5563` |
| 弱文字 | `--color-text-tertiary` | `#8b95a5` |
| 默认边框 | `--color-border` | `#e3e8ef` |
| 强边框 | `--color-border-strong` | `#d5dce7` |
| 聚焦边框 | `--color-border-focus` | `#b6c0ce` |
| 品牌强调 | `--color-brand` | `#8f482f` |
| 运行按钮 | `--color-run` | `#ead5cf` |
| 错误 | `--color-danger` | `#dc2626` |
| 成功 | `--color-success` | `#15803d` |

使用规则：

- 默认按钮和导航项透明；hover 使用浅容器色。
- 品牌色仅用于 tab 激活线、少量选中强调和关键边框。
- 蓝色仅用于文本选择、链接和代码语法，不作为产品主色。
- 截图中的青色圆形是鼠标控件，不属于产品视觉元素。
- 禁止装饰性渐变、彩色光斑、背景圆球和大面积紫色、棕色或蓝色主题。
- 错误、警告、成功色只表达状态，不作为装饰。

### 2.2 字体和字重

- UI 正文：`--font-body`，Inter + 中文系统字体。
- UI 标题：`--font-headline`，Manrope + Inter + 中文系统字体。
- 代码：`--font-mono`，JetBrains Mono。
- UI 正文和普通标签使用 `400`。
- 当前项、按钮名称、节点标题和页面标题最多使用 `500`。
- UI 禁止 `600/700`；数字统计的主数值可以使用 `600`，但说明文字仍为 `400`。
- Markdown、EPUB、用户文档中的标题字重属于内容语义，不受 UI 字重限制。
- 不使用负字距；不按视口宽度缩放字号。

推荐字号：

| 场景 | 字号 |
| --- | --- |
| 页面标题 | `20px` |
| 区块标题 | `16px` |
| 正文、按钮、tab、节点内容 | `14px` |
| 节点标题、辅助标签、状态 | `12px` |
| 代码 | `13-14px` |

### 2.3 间距、圆角和阴影

- 基础间距单位为 `4px`；常用间距为 `8/12/16/24/32px`。
- 图标按钮固定为 `32px` 或 `36px`，同一工具栏不得混用。
- 普通按钮、输入框和菜单项圆角为 `8px`。
- 项目卡片和设置区块圆角不超过 `8px`。
- 画布节点和浮动编辑器属于 framed tool，统一使用 `12px` 圆角。
- 胶囊只用于工具栏、分段选择和状态标签，不用于普通命令按钮。
- 普通页面卡片不使用阴影；菜单使用下拉阴影；浮动工具使用画布阴影。
- 画布节点使用独立节点阴影，并保持原 `shadow-xl` 的明显悬浮效果；节点需要与无限画布形成清楚的纵深关系，不能为了“轻量”弱化为贴边阴影或不可见阴影。
- 禁止嵌套卡片阴影和多层装饰阴影。

阴影实现规则：

- 阴影统一由 `--shadow-node`、`--shadow-canvas`、`--shadow-dropdown` 和 `--shadow-overlay` 语义令牌定义。
- 组件必须使用 `zenme-shadow-node`、`zenme-shadow-canvas`、`zenme-shadow-dropdown` 或 `zenme-shadow-overlay` 语义类；这些类直接设置 `box-shadow: var(...)`。
- 禁止使用 `shadow-[var(--shadow-*)]`。当前 Tailwind 编译器会把这类任意值误判为 `--tw-shadow-color`，不会生成实际 `box-shadow`，界面最终会完全没有阴影。
- 新增阴影类型时，先增加全局令牌和对应语义类，再在组件中引用；不得在业务组件内散落自定义 `box-shadow` 或任意 Tailwind 阴影值。
- 验收时不能只检查源码类名，还必须检查编译 CSS 或浏览器计算样式，确认目标元素的 `box-shadow` 不为 `none`。

## 3. 应用框架

### 3.1 固定结构

- 展开侧栏宽 `280px`，收起侧栏宽 `48px`。
- 顶部 tab 栏高 `40px`，从侧栏右侧开始。
- 主内容从侧栏和 tab 栏之后开始，内部滚动条不得穿过顶栏。
- Electron 使用无框窗口；拖拽区域标记 `data-desktop-drag-region`，交互元素标记 `data-desktop-no-drag`。
- 页面和画布使用父容器高度，不使用裸 `100vh` 抢占窗口。

### 3.2 侧栏

内容顺序：展开按钮与品牌、新建项目、项目搜索、项目列表、首页、设置、本地模式。

- 所有侧栏命令默认透明，hover 才出现浅灰背景。
- 当前项不显示白色卡片，只使用文字色或 `500` 字重区分。
- 项目顺序稳定：点击、打开、保存都不能重排；置顶只改变置顶分组。
- 项目操作使用图标菜单，提供重命名、置顶/取消置顶等操作。
- 收起后只保留可识别图标，并提供 tooltip。

### 3.3 顶部 tab

- tab 保持打开顺序，切换不重排；新 tab 追加到末尾，最多 9 个。
- 当前 tab 只使用底部品牌色细线和 `500` 字重。
- 点击项目 tab 名称打开统一重命名弹层；不使用 inline 输入框。
- 关闭当前 tab 后切换到相邻 tab 或首页。
- tab 文字必须截断，不得挤压窗口控制按钮。

## 4. 页面与通用控件

### 4.1 页面布局

- 首页、项目列表和设置页采用无框的内容带，不把整个页面包进大卡片。
- 页面内容宽度和边距应响应窗口；设置弹窗上下至少保留 `80px` 安全边距。
- 不使用超大 hero 标题；工作台页面首标题不超过 `20px`。

### 4.2 按钮

- 熟悉动作优先使用 Lucide 图标；陌生图标必须有 tooltip。
- 普通命令：透明或白底，hover 浅灰。
- 主提交：使用运行色或深色圆形发送按钮；同一上下文只出现一个主操作。
- 危险操作：默认中性，hover 或确认阶段变红。
- 禁用态保留布局和标签，降低对比度并禁止指针操作。
- 保存按钮在有未保存更改时必须清晰可见；保存成功后页面或弹窗保持打开并反馈状态。

### 4.3 输入与选择

- 输入框白底、1px 边框、8px 圆角；focus 使用聚焦边框或轻 ring。
- placeholder 使用弱文字色；输入文字 `400`。
- 二元设置使用开关或 checkbox；模式使用 segmented control；模型等选项使用菜单。
- 输入获得焦点必须显示插入光标；不可编辑画布区域必须隐藏插入光标。
- 模式切换、失焦和重新聚焦不得清空或改写用户输入。

### 4.4 弹层与菜单

- 下拉菜单宽度稳定、8-12px 圆角、白底、浅边框和单层阴影。
- 模态弹窗上下保留至少 `80px`，标题与底部操作固定，内容区独立滚动。
- Escape 关闭最上层弹层；点击遮罩可关闭预览，但有未保存表单时必须先确认。
- 保存不自动关闭编辑服务商等需要连续配置的弹窗。
- 不可恢复的删除操作必须使用二次确认弹窗，不得从菜单项直接执行。
- 删除确认弹窗必须显示具体对象名称、不可恢复说明、普通“取消”按钮和危险色确认按钮；确认按钮应写明对象，例如“删除项目”，不能只写“确定”。
- 删除执行期间禁用关闭、取消和确认按钮并显示进行中状态；失败时保留弹窗并在原位显示错误。

## 5. 无限画布

### 5.1 画布基础

- 画布根容器使用 `h-full`，工具不得覆盖内容边界。
- 缩放范围为 `20%-250%`；Ctrl + 滚轮在节点上方同样缩放画布。
- 顶部、侧边和底部工具栏保持屏幕物理尺寸，不随画布缩放。
- 双击空白画布打开添加菜单；双击输入区或节点控件不触发菜单。
- 粘贴文本创建文本节点，粘贴图片创建图片节点，复制节点后粘贴复制节点；粘贴不复制连线，也不自动选中新节点。

### 5.2 节点统一结构

节点由“标题行 + 8px 间距 + 主框”组成：

- 标题行高 `20px`，使用 `12px/500` 和弱文字色。
- 主框默认圆角 `12px`、1px 边框、白底和统一节点阴影。
- 文本和图片生成默认主框尺寸统一为 `520 × 260`。
- 主框尺寸不包含标题行；浮动工具和输入控件不参与节点尺寸计算。
- 节点最小尺寸必须固定，动态文案、加载态和 hover 控件不能改变布局。
- 用户调整过尺寸的节点保留用户尺寸；仅迁移已知历史默认尺寸。

### 5.3 节点状态

- 默认：浅边框，隐藏辅助控件。
- hover：显示可用的加号和内联操作，不改变尺寸。
- selected：主框使用深色 1px 边框；显示上方工具栏和下方输入控件。
- focus-within：等同 selected 的边框反馈，输入光标正常显示。
- renaming：只显示名称输入，隐藏工具栏、连接点、缩放柄和其他操作。
- dragging：全局隐藏节点浮动控件、内联控件、连接点和缩放柄。
- loading：保留旧结果，在主框内显示轻量加载状态；成功后原位替换。
- error：在下方输入控件内显示受控错误，不改变主框尺寸。

### 5.4 工具栏与输入控件

- 上方工具栏和下方输入控件均以主框水平中心对齐。
- 两者使用逆缩放保持合理物理尺寸，缩放画布时不能无限变大或缩小。
- 上方工具栏为白色胶囊、浅边框、统一阴影；图标按钮 `32/36px`。
- 文本与图片节点的下方 AI 输入控件为白色 framed tool，默认宽 `640px`、最小高 `220px`，最大不超过可视区域；与主框间距在屏幕空间保持 `12px`。
- 点击节点主区域即可选中，不要求点击标题；输入控件内部点击不得拖动节点。
- 模型、比例、清晰度等选择分别记住同模态上一次选择。

### 5.5 连接点

#### 连接语义

- 画布中的持久连线统一表达有向关系：父节点或上游节点为 source，子节点或下游节点为 target，视觉方向为 `父节点右侧 → 子节点左侧`。
- 普通输出连接用于创建或连接下游节点；“向前连接”用于为当前节点选择上游节点。向前连接完成后必须把关系归一化为 `上游节点 → 当前节点`，不得按用户拖拽方向反向保存。
- 禁止节点连接自身。上下文连接只能在成对的上下文 source/target 端点之间建立，普通输出端点不得吸附上下文目标端点，上下文 source 也不得吸附普通输入端点。
- 连接拖到画布空白处时，普通输出连接可以打开节点创建菜单；向前连接不得打开创建菜单，只能选择已有的兼容上游节点。

#### 触发控件与真实锚点

- 左右两侧的 `+` 都只是发起拖线或打开连接菜单的手势控件，不是持久连线的视觉锚点，也不参与静态边的最终几何计算。
- 连接完成后必须移除 action/context 触发 handle 的临时语义，静态边统一锚定到父节点右边框的标准输出端点和子节点左边框的标准输入端点。
- 静态边必须从节点边框连接到节点边框，不得停在浮动 `+`、标题、工具栏、下方输入控件或端点附近的空白处。
- 右侧 `+` 与标准输出端点保持同一水平线；左侧向前连接控件与标准输入端点保持同一水平线，但控件位置不得改变最终边的锚点。

#### 端点几何与显隐

- 标准输入端点位于主框左边框，标准输出端点位于主框右边框；两者均相对实际主框高度 `50%` 垂直居中，外置类型标题不参与中心计算。
- 图片节点以实际图片框为主框；文本、任务、分析结果等节点以各自可见 bordered frame 为主框。下方 AI 输入控件、浮动工具栏和节点外状态标签均不得计入端点中心。
- 所有普通节点复用相同的可见端点尺寸、边框和定位方式，不得为单一节点类型扩大可见 handle 或改变 React Flow 的测量几何。需要扩大命中范围时使用不改变可见锚点位置的独立透明热区。
- 非 hover、非选中、非 focus-within 状态下，所有可见端点白点均隐藏；节点 hover、选中或内部控件获得焦点时，才显示该节点已有连线对应的输入/输出端点。
- 无上游连线时不显示左侧标准输入白点；即使节点 hover 或选中，也不得显示不存在关系的普通输入端点。空的图片生成节点等无上游关系的节点同样遵循此规则。
- 无下游连线时不显示右侧标准输出白点，由同位置的 `+` 提供创建或连接入口；存在下游连线时，输出白点仅在节点 hover、选中或 focus-within 时显示。
- 正在拖线时，可连接目标端点可以临时显示，用于表达有效吸附位置；拖线结束后立即恢复上述交互态显隐规则。
- 节点重命名、拖动或处于明确要求隐藏辅助控件的状态时，连接点和 `+` 一并隐藏；状态结束后恢复。
- 节点尺寸、内容高度或图片比例变化后必须同步更新 React Flow 节点测量信息，使端点、边路径和边框中心保持一致。

#### 连线显示状态

- 普通状态：连线两端节点均未选中，使用淡色半透明中性灰，建议 `rgba(113, 113, 122, 0.42)`、`1.75px`。
- 节点相关状态：任一端节点被选中，使用中色半透明中性灰，建议 `rgba(82, 82, 91, 0.62)`、`2.2px`。
- 连线选中状态：连线自身被选中或获得键盘焦点，使用较重但不接近纯黑的半透明中性灰，建议 `rgba(63, 63, 70, 0.78)`、`2.7px`，可增加轻微阴影。
- 连线自身选中状态优先于端点节点选中状态；hover 可使用介于后二者之间的反馈，建议 `rgba(82, 82, 91, 0.68)`、`2.3px`。
- 所有状态保持透明度，使多条连线交叉时能看出叠加关系；不得使用不透明纯黑粗线。颜色和线宽切换使用约 `120ms` 的短过渡。
- 可见线条之外应提供更宽的透明点击热区，确保点击和键盘焦点选中稳定，但热区不得改变可见路径或端点位置。

#### 持久化与历史兼容

- 新保存的边不得持久化 `+` 对应的 action handle；上下文连接完成后也必须保存为规范化的上游到下游关系。
- 读取历史边时，应把遗留 action/context handle 归一化为标准 source/target 端点。
- 历史任务节点边缺少 target handle 时，渲染层必须补齐任务节点左侧标准输入端点，不能回退到节点包围盒推算导致连线与白点之间出现空白。
- 任何节点类型新增、迁移或更换主框结构时，都必须验证普通连接、向前连接、历史边、缩放和调整尺寸后的端点位置。

### 5.6 文本节点

- 保留纯文本、Markdown、代码模式和格式工具；切换模式不得丢内容。
- 代码模式显示语言子选项；Markdown 预览和编辑共享同一份源内容。
- 选中后下方展开 AI 对话控件；提交后立即创建独立 AI 回复子节点，运行状态、计时、结果和错误均显示在子节点，不在输入控件内显示临时任务状态。
- 同一源节点的直属生成任务运行期间禁用提交按钮；失焦、重新选中或缩放画布不得丢失运行状态。任务完成后允许再次提交并创建新的并列子节点。
- 文本节点、阅读笔记等文本类节点使用相同对话交互。

#### 强管理节点原型

- 强管理节点与普通文本节点并存，使用相同的外置类型标题、主框圆角、边框、节点阴影、连接点和缩放交互。
- 外置标题固定显示节点类型“强管理节点”；可检索的强名字位于主框 Header，不得继续复用外置类型标题作为名称。
- Header 作为主框内独立的信息框固定在顶部，使用 `1px` 中性边框、浅色底和 `8px` 圆角，包含强名字、创建时间和标签区；仅正文区域滚动，滚动内容不得遮挡或带走 Header。
- 强名字始终使用固定尺寸的输入框，空值时显示“未命名节点”；聚焦前后不得替换 DOM、改变字号或引起 Header 尺寸跳动。名称编辑期间保留清晰输入光标，并遵守全局重命名时隐藏其他控件的规则。
- 创建时间使用次级文字显示到分钟；标签采用紧凑的柔和色标签样式，同名标签颜色保持一致，单个标签超长时截断且不撑开节点。点击 `+` 后使用宽度约 `224px` 的紧凑浮层承载搜索框、项目已有标签和“创建新标签”入口，输入框必须显示文本光标，选择后关闭浮层。Header 中已经添加的标签本身也是颜色面板触发器，点击标签直接打开九色浮层；标签内的删除 `X` 使用独立命中区域，不得同时触发颜色面板。标签列表右侧不得使用无操作价值的选中勾号；固定提供颜色方块和删除 `X`。颜色入口与九个颜色选项不绘制矩形按钮外框，只保留色块、悬停和键盘焦点反馈；`3 × 3` 九色面板必须通过 Portal 作为锚定颜色入口的独立浮层显示，不得进入标签列表文档流或改变列表高度。删除和改色均按项目级选项处理。
- 默认主框尺寸为 `560 × 380px`，最小尺寸为 `360 × 260px`；动态标签换行只占用 Header 内部空间，正文仍使用剩余高度滚动。
- 名称、标签和创建时间均为持久化元数据，供后续搜索和筛选使用；搜索结果界面不属于本原型范围。
- 正文编辑区获得焦点时必须显示文本插入光标，使用 `caret-color: #18181b` 覆盖画布空白区的透明光标规则。

#### 任务节点

- 任务节点沿用统一的“外置类型标题 + 悬浮主框”结构。外置标题只显示节点类型“任务”，任务名称放在主框固定 Header 中。
- 默认尺寸为 `560 × 460px`，最小尺寸为 `420 × 360px`；使用 `--shadow-node` 语义阴影、`12px` 主框圆角和中性边框。
- Header 固定在主框顶部，不随子任务列表滚动，并与强管理节点使用相同的内嵌信息框结构：距主框四周 `12px`、浅灰背景、`1px` 中性边框和 `8px` 圆角。任务名称输入框使用白底，采用正常正文大小 `14px` 和中等字重，聚焦前后不得替换 DOM、改变字号或改变高度。
- 状态、优先级、复杂程度、紧急程度和时间元数据收纳在 Header 的单行紧凑工具栏中，不得以两列字段网格或大卡片展示。
- 工具栏常态由四个 `36px` 方形属性按钮、两个自适应时间项、一个子任务完成摘要和一个 `36px` 折叠按钮组成：状态显示当前语义图标；优先级显示当前 `1 / 2 / 3`；复杂程度显示当前 `中 / 简 / 繁`；紧急程度显示站立、步行、跑步三个小人图标。创建时间和修改/完成时间使用时钟图标加短时间值；时间项之后使用紧凑的等宽数字显示 `已完成数/总数`，最后使用上/下箭头收起或展开子任务列表。
- 折叠高度不得使用固定猜测值，应根据当前 Header 的实际渲染高度加节点外边距计算，并在 Header 下方保留清晰的底部留白；展开时恢复折叠前保存的高度。选中折叠态节点时仍显示 `NodeResizer`，允许调整宽度和紧凑外框高度；折叠态最小高度为 `176px`，且调整折叠态尺寸不得覆盖已保存的展开高度。
- 新建任务节点默认使用收起态，初始高度采用刚好容纳 Header 与必要外边距的最小紧凑高度，并预存标准展开高度；首次展开后恢复标准展开尺寸，后续折叠与展开则使用实际 Header 高度和用户最后保存的展开高度。
- 属性按钮不显示常驻字段 label，完整含义通过 hover tooltip、`title` 和 `aria-label` 提供。单击按钮后弹出紧凑菜单，菜单中一次显示该属性的全部选项、图标和文字说明；切换后立即收起。
- 属性菜单使用节点级单一打开状态：打开另一个属性菜单时关闭前一个；节点失焦、失去选中、点击画布空白处或完成选择时关闭，不允许多个菜单叠加或失焦残留。
- 属性菜单采用纯图标横排布局，每个选项使用约 `36px` 的稳定方形命中区域，不显示右侧文字描述。优先级使用填充圆形数字徽标：`1` 红、`2` 黄、`3` 蓝，数字为白色；Header 当前值和菜单选项必须使用同一视觉。完整文字只存在于 tooltip、`title` 和 `aria-label`。
- 属性按钮使用浅底、浅边框和轻量 hover 状态，状态图标保留绿色或黄色语义色；弹出菜单遵循通用白底、浅边框、单层阴影规范。
- 创建时间、修改时间或完成时间只显示时钟图标和格式化时间值，可见区域不重复显示“创建时间”等 label，完整语义放入 tooltip 和可访问名称。
- 标签视觉和项目级共享规则与强管理节点一致；新增标签选择器复用同一紧凑浮层宽度、标签颜色和删除语义。
- 任务进度使用 `36px` 绿色语义圆环：轨道使用浅绿色、进度弧使用中等绿色、圆心百分比使用深绿色，不使用横向进度条或高饱和品牌色。圆心只显示整数百分比，不显示“执行进度”、状态或完成数等可见 label；完整语义通过 `title` 和进度条可访问属性提供。
- 进度圆环放在 Header 元数据工具栏最左侧、执行状态按钮之前；子任务标题区只显示标题和数量。
- 子任务列表位于 Header 下方的内部滚动区，每行显示状态图标、任务名称和状态文字；长名称截断，不得撑宽节点。
- 任务节点的左侧输入端点只在存在上游连线且节点处于 hover、选中或 focus-within 时显示；右侧输出加号与其他节点保持一致。任务节点允许连接任意节点类型。
- 任务节点左侧普通输入端点必须与文本节点使用完全相同的尺寸、边框位置、显隐规则和连接锚点，不得单独扩大 handle 或改变 React Flow 的端点测量几何。
- 文本、强管理节点和任务节点右侧必须提供独立的上下文目标端点。文本节点左侧“向前连接”控件连接任务节点或另一个文本类节点时，只允许吸附该右侧专用端点，最终连线方向再通过统一规则归一化为 `上游节点 → 当前文本`。
- “向前连接”的 source handle 与右侧上下文 target handle 必须成对使用；普通左侧 target handle 和普通右侧 source handle 不参与上下文连接。拖线期间不得同时激活两类目标端点，以免临时连线在节点左右两侧反复吸附和抖动。
- 任务节点右侧拉线菜单直接复用画布双击添加菜单的菜单项、顺序、图标、说明和资源分组。菜单创建或上传的节点自动与当前任务建立连线，避免出现两个功能相近但内容不同的节点创建菜单。
- 只有下游任务节点进入子任务列表和进度计算，其他下游节点只表示任务关联事项，不显示为子任务且不影响进度。

### 5.7 图片节点

- 上传图和生成图使用真实宽高比，不裁切、不拉伸、不填黑边。
- 画布显示尺寸使用统一外接圆算法：以 `280 × 280` 的对角线为固定直径，任意宽高比内接于同一参考圆。
- 原图用于下载和后续处理；画布预览最长边 `1200px`、WebP 质量 `0.88`。
- 图片上方工具栏提供最大化和下载，样式与文本工具栏一致。
- 最大化预览显示原图、提示词、模型、质量和宽高比。

### 5.8 图片生成与参考图处理

- 双击画布可创建独立图片生成节点，不需要参考图。
- 产品界面只使用“图片生成”节点；从现有图片的操作入口创建时，通过连线将来源图片加入候选并默认选为参考。
- 图片生成输入控件顶部使用紧凑缩略图列展示用户已选参考图片；输入 `@` 或点击“+”打开已连接图片选择器，支持搜索、多选和取消；选择一张图片后立即关闭选择器。
- 参考选择器默认关闭；选中或重新选中图片生成节点时只展开 AI 输入控件，不得自动打开参考选择器。
- 已选参考标签最多显示 10 个 Unicode 字符，超出后显示 `...`，悬停仍可查看完整名称。无参考时保留“+”入口，悬停提示为“参考”。缩略图不得改变主节点尺寸或下方输入控件的屏幕尺度补偿。
- 图片生成和图片编辑是同一节点的两种任务语义，不得提供独立的图片编辑节点，也不得根据 URL 猜测任务类型。
- 历史数据兼容必须在持久化迁移层一次性完成；渲染组件不得保留旧节点类型分支或通过旧字段临时伪装新节点。
- 没有参考图时，以用户描述进行纯图片生成；存在参考图时，根据用户指令选择精确编辑或基于参考图重新生成。精确编辑应最大限度保持主体身份、结构、构图、光照和未指定区域。
- 每次生成都在源节点下游创建独立结果子节点；运行中先显示固定尺寸占位框，成功后只回填该占位节点。历史图片结果和源节点不得被后续请求覆盖。
- 图片直属结果运行期间禁用源节点生成按钮；计时与失败信息属于结果子节点，并随画布持久化。
- 图片生成节点共享最近一次图片选项偏好，包括模型、宽高比和画质；选项改变后立即记忆，新节点沿用，已有节点的独立配置不得被全局偏好覆盖。

### 5.9 阅读器节点

- 展开和最小化保持当前位置、页码、目录高亮和面板尺寸。
- 重新展开后目录滚动到当前项。
- 阅读正文属于用户内容，可保留出版物标题层级和字重。
- 阅读器内部滚动不得推动画布缩放；仅 Ctrl + 滚轮交给画布。

### 5.10 音乐工作流节点

- 音乐资产、播放器和歌词节点均遵循统一的“外置标题行 + 主框”结构；所有标题使用 `EditableNodeTitle`，重命名时隐藏连接点和其他操作控件。
- 音乐资产主框固定为 `360 × 112px`；播放器主框固定为 `560 × 176px`，内部依次展示标题、真实波形、播放进度和播放设置。
- 歌词节点默认尺寸为 `560 × 176px`、最小尺寸为 `420 × 176px`，支持展开为 A4 阅读面板和用户调整尺寸。
- 歌词正文占用主框剩余高度并在内部滚动；节点内部不重复展示“来自播放器”说明或成功状态条。
- 播放器常规控制包括播放/暂停、进度、静音、音量、倍速和循环；右侧拉线菜单只提供“歌词”操作。
- 歌词获取失败时显示明确错误；获取耗时位于主框外侧右上角，使用 `s`、`m`、`h` 紧凑单位。
- 歌词曲库候选只比较标题、歌手与音频时长；专辑信息只作为只读元数据。
- 播放器只展示由真实音频计算得到的波形响度包络，禁止随机、循环或固定数据模拟波形。
- 波形覆盖完整歌曲时间范围，并使用 RMS 分桶和全曲稳健归一化。
- 音乐类节点使用 `NodeFrame` 和 `--shadow-node` 语义阴影；选中边框、端点和输出加号与其他节点一致。
- 音乐资产只允许创建或定位唯一播放器；播放器是歌词节点的直接上游。

## 6. 反馈、文案和可访问性

- 保存状态只使用：`正在保存到本地`、`已保存到本地`、`本地保存失败`、`本地服务不可用`。
- 按钮使用短动词：`新建项目`、`重命名`、`置顶`、`保存`。
- 不在主界面写教程式说明；空状态只说明下一步动作。
- 图标按钮必须有 `title` 或可访问名称；键盘 focus 可见。
- 文本对比度不低于常规桌面工具要求；状态不能只靠颜色表达。
- 动画以 `120-220ms` 的 opacity、颜色和轻位移为主，不使用弹跳或持续装饰动画。

- 方形图标：`public/brand/icons/zenme-logo-{16,24,32,48,64,128,256,512,1024}.png`。

## 8. 实现约束

- 新增颜色、阴影、尺寸先进入 token 或共享组件，再在业务组件使用。
- 优先复用 `NodeFrame`、节点工具栏、模型选择器、浮动菜单和统一输入控件。
- 不新增装饰渐变、嵌套卡片、无功能装饰或随意的 `font-semibold/font-bold`。
- 特殊样式必须在本文件记录适用范围；“现有页面如此”不是新增例外的理由。
- 每次 UI 修改至少运行 `npm run lint`、`npm test`、`npm run build`。

## 9. 一致性验收清单

提交 UI 改动前逐项确认：

1. 是否使用已有 token、字号、圆角和阴影？
2. 默认、hover、selected、focus、disabled、loading、error 是否完整？
3. 控件出现后是否引发布局跳动或文字溢出？
4. 画布缩放后，上下浮动控件是否保持合理物理尺寸并居中？
5. 节点连接点是否相对主框居中，拖动/重命名时是否隐藏？
6. 模式切换、失焦、重开页面是否保留用户内容和选择？
7. 是否存在无意义背景、渐变、过重阴影、粗体或大圆角？
8. 文案是否符合本地优先语义？
9. 键盘、tooltip、focus 和 Escape 行为是否可用？
10. 桌面窗口、窄窗口和不同画布缩放下是否无重叠和遮挡？
