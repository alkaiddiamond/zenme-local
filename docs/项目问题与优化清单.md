## 2. 高优先级问题

### 2.1 用户鉴权与权限边界未收口

现状：

- 登录、注册、忘记密码、更新密码等 Supabase Auth 基础页面已存在。
- Supabase 主业务表已通过 RLS 按 `owner_id` 隔离。
- 业务路由和 API 层已完成首轮权限收口，但仍需要真实登录态端到端验证。

已处理：

- 中间件已对未登录页面访问重定向到 `/auth/login`。
- API 未登录访问会返回 `401`。
- Supabase 环境变量缺失时仅允许本地/测试环境跳过 proxy 鉴权；`VERCEL_ENV=preview` 和 `VERCEL_ENV=production` 会 fail closed：API 返回 `500`，页面跳转到 `/auth/error?error=supabase_config_missing`。
- 已新增 `lib/supabase/proxy.test.ts` 和 `proxy.test.ts`，覆盖本地/测试 Supabase 环境变量缺失时跳过检查、生产和预发缺配置 fail closed、未登录 API 返回 `401`、未登录页面重定向、认证页放行、已登录请求放行，以及 proxy matcher 对应用/API 路由和静态资源的匹配边界。
- `/auth/error` 已改为通过白名单错误码映射展示中文安全文案，不再回显 URL 中的原始 `error` 值；`/auth/confirm` 失败时只传稳定错误码，不再把 Supabase 原始错误 message 写入 URL。
- `/auth/confirm` 成功后的 `next` 跳转已通过 `getSafeAuthRedirectPath()` 收敛为站内相对路径，避免外部 URL 或畸形路径造成开放重定向。
- 注册确认邮件和密码重置邮件的回调地址已统一走 `/auth/confirm?next=...`，确保邮箱 token 校验、错误码收口和安全跳转都经过同一条服务端确认链路。
- 登录、注册、忘记密码和更新密码表单已改为通过 `getAuthFormErrorMessage()` 映射 Supabase Auth 错误，不再直接展示 provider 原始 `error.message`；忘记密码和更新密码页面文案已统一中文化。
- 更新密码成功后已改为回到 Zenme 产品首页；旧 `/protected` Supabase Starter 示例页已收口为产品首页重定向，并移除模板布局内容，避免用户完成认证后进入示例页面。

- 已新增 `lib/supabase/auth.test.ts` 中的鉴权错误边界检查，要求 `ApiAuthError` 只能使用稳定字符串字面量作为对外错误文案，避免后续误把 Supabase provider、数据库或内部异常 message 包装成鉴权响应返回给前端。
- `/api/ai/*` 已接入 `requireUser()`。
- `/api/reading/*` 已接入 `requireUser()`。
- 阅读资产、笔记、进度已通过 Supabase RLS 和 repository 查询按 `owner_id` 隔离。
- 已新增 `requireReadingAssetAccess()`，用于显式校验阅读 asset 可见性和 project 匹配。
- 已新增 `requireReadingNoteAccess()`，用于显式校验单条阅读笔记可见性。

已处理：

- `/api/reading/**` 已接入登录校验。

- 阅读资料登记、payload 加载、原文件读取、封面读取和 EPUB 内部资源读取接口已对 Supabase Storage `Invalid key` 与对象路径做用户侧错误收口，不再把完整 object key、用户 ID、项目 ID 或原始文件名透传到前端错误提示。

- 浏览器侧 `createSignedUrl()` 已增加当前用户与 Storage path 首段匹配校验，避免调用方误把其他用户路径传入签名 URL helper；Storage RLS 仍作为最终权限防线。
- 画布快照保存写入 `thumbnail_path` 前会校验缩略图 Storage path 首段必须是当前用户 ID，避免误把其他用户路径写入项目元数据。
- 项目创建时已显式写入 `projects.owner_id` 和初始 `canvas_snapshots.owner_id`，不再只依赖数据库默认值；初始快照创建失败时会尽量删除刚创建的项目，避免半成品项目残留。
- 阅读 payload/file/cover/EPUB 资源读取和 notes/progress 操作已通过 `requireReadingAssetAccess()` 显式校验 asset 可见性和项目匹配。
- 单条阅读 note 更新/删除已通过 `requireReadingNoteAccess()` 显式校验 note 可见性。
