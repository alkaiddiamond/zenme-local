# Zenme Local PRD

版本：0.1.0
基线日期：2026-07-10
状态：当前实现基线

## 1. 产品定位

Zenme Local 是面向个人创作、阅读与 AI 辅助工作的本地桌面无限画布。用户可以在一个项目中组织文本、图片、文件、书籍、笔记和 AI 生成结果，并通过连线表达上下文关系。

产品坚持以下边界：

- 纯本地、单用户、桌面优先。
- 无账号、无远程数据模式、无自动上传或云同步。
- 用户数据由本机文件系统持有，数据目录可查看、迁移、备份和恢复。
- 模型调用是唯一需要联网的核心能力，密钥由用户自行配置并保存在本机。

## 2. 应用结构

### 2.1 桌面壳

- Electron 提供原生窗口、任务栏图标、自绘标题栏、窗口控制与数据目录能力。
- 应用服务只绑定 `127.0.0.1`；管理 API 拒绝非 loopback、跨源和跨站请求。
- 主窗口不得导航到外部页面；HTTP(S) 外链交给系统浏览器。

### 2.2 项目工作区

- 左侧侧栏包含新建项目、搜索、固定顺序项目列表、首页、设置和本地模式状态。
- 顶部显示已打开项目 Tab，支持切换、关闭和重命名；打开项目不改变列表顺序。
- 侧栏可收起；窗口布局和滚动区域不得侵入标题栏。

## 3. 项目与本地持久化

- 支持新建、打开、搜索、重命名和删除项目。
- 搜索栏下方提供“收藏”区；用户可从项目菜单添加收藏或取消收藏，收藏项目同时在完整项目列表名称前显示实心星标，并在收藏区提供快捷入口。
- 收藏与置顶相互独立：收藏不改变完整项目列表顺序；删除项目时同步清理收藏记录，搜索条件同时作用于收藏区与项目列表。
- 左侧项目列表的 `...` 菜单提供“添加收藏/取消收藏”“置顶/取消置顶”和“删除”；项目重命名继续使用项目行的独立入口。
- 删除项目属于不可恢复的危险操作，必须显示二次确认弹窗，明确展示项目名称及将被删除的画布和本地文件；只有用户再次点击“删除项目”才执行删除。
- 删除成功后必须同步清理项目列表、置顶记录、固定顺序和已打开标签；删除当前项目时跳转到下一个仍然存在的已打开项目，没有可用项目时返回首页。
- 项目元数据、画布快照、缩略图、普通文件和阅读资料均位于项目目录。
- 自动保存间隔由本地设置驱动，默认 5 秒。
- 保存状态只表达本地保存结果，不出现云端同步文案。
- 项目和节点 ID 必须是安全路径段，任何 API 都不得据此写出数据目录。

## 4. 无限画布

- 支持平移、缩放、框选、拖拽、连线、分组、撤销与重做。
- 连线支持点击和键盘焦点选中，并按普通淡色、端点节点选中中色、连线选中重色三级展示；所有级别保持一定透明度以呈现交叉叠加，选中后可使用删除快捷键移除。
- 鼠标位于画布空白区、节点内容或节点控件上时，均支持 `Ctrl/Cmd + 滚轮` 以鼠标位置为中心缩放画布；无修饰键的滚轮继续用于节点内部滚动。
- 画布缩放范围为 `20%–250%`，所有按钮、滚轮和视口恢复逻辑使用同一边界。
- 节点端点位于内容框纵向中点；未连接的输入端点不显示。
- 输出侧显示 `+` 快捷入口，可继续创建并连接下游节点。
- 节点选中时显示统一边框与悬浮工具栏；点击节点内容区域即可选中。
- 支持重命名的节点在编辑标题时必须显示文本插入光标，并暂时隐藏格式工具栏、AI 对话控件、连接控件和缩放手柄；提交或取消后恢复。
- 拖动节点期间隐藏节点悬浮控件、连接控件、缩放手柄和多选工具条，拖动结束后恢复，避免控件遮挡画布和产生误操作。
- 悬浮工具栏和下方对话控件采用屏幕尺度补偿，缩放画布时保持可用尺寸并相对节点居中。
- 画布支持 `Ctrl/Cmd+C`、`Ctrl/Cmd+X` 和 `Ctrl/Cmd+V` 复制、剪切及粘贴所选节点；粘贴时生成新节点 ID、保持节点相对布局和分组关系，但不复制任何连线。
- 粘贴创建的节点默认不选中、不获取输入焦点，也不改变粘贴前已有节点的选择状态。
- 系统剪贴板中的一张或多张图片可直接粘贴为本地图片节点，并沿用项目文件上传、预览和持久化链路。
- 系统剪贴板中的纯文本可直接粘贴为文本节点；焦点位于输入框、文本编辑器或可编辑区域时保留系统原生复制粘贴行为。
- 粘贴位置优先采用鼠标最近所在的画布坐标，无法取得时使用当前画布视口中心。
- 画布快照限制为 20 MB、5000 个节点和 10000 条边；缩略图限制为 WebP 且不超过 5 MB。

## 5. 文本节点

- 文本、Markdown 和代码片段统一为文本节点，不再提供新的独立文本生成节点入口。
- 顶部工具栏保留粗体、斜体、下划线、行内代码、新增内容及显示模式切换。
- 显示模式包括纯文本、Markdown、代码；代码模式可选择语言。
- AI 文本回复默认按 Markdown 模式记录和展示，支持标题、列表、引用、行内代码、代码块及 GFM 管道表格；宽表格在节点内部横向滚动，不得退化为带竖线的普通文本。历史 AI 回复也按 Markdown 解释，不再以保留 Markdown 符号的纯文本方式展示。
- 模式切换、失焦与重新聚焦不得清空内容。
- 点击文本节点后，在下方展开 AI 对话控件；输入提示词后，基于节点内容和上游上下文生成结果。
- 阅读笔记等文本类节点采用相同的下方对话交互。
- 历史 `textGeneration` 节点继续兼容渲染，但不能再新建。

## 6. 图片生成与参考图处理

- 上传图片和生成图片采用同一画布显示算法；相同宽高比必须得到相同显示尺寸，不因图片来源或实际像素数而变化。
- 所有图片框采用同一外接圆规则：以 `280 × 280` 正方形的对角线作为固定直径，按图片真实宽高比计算内接矩形；任意比例均保持相同对角线长度，不限制为预设比例区间。
- 非标准比例读取图片实际宽高计算，不强制归入预设比例；源文件分辨率只影响下载结果。
- 上传图片的画布预览采用最长边 `1200px`、质量 `0.88` 的 WebP；本地原图保持原始字节，用于最大化查看、下载和后续图片处理。
- 图片上方白色工具栏提供全屏查看和下载。
- 下载文件名使用可追溯的时间戳/元数据命名。
- 图片能力统一使用“图片生成”节点，不再向用户提供独立的“图片编辑”节点；节点上部为结果框，下部为获得焦点后展开的提示词控件。
- 图片生成和图片编辑不是两种节点类型，而是同一节点根据参考集合产生的任务语义：没有参考图时以纯生成为主；存在参考图时，根据用户指令执行精确编辑或以参考图为基础生成新图片。
- 旧画布快照首次读取时必须从 `v1` 一次性迁移并原子回写为 `v2`：旧 `imageEdit` 节点转为 `imageGeneration`，旧图片任务字段转为统一字段，参考关系由连线恢复，并清除节点内重复保存的来源 URL；迁移后运行时和新快照不得继续写入旧结构。
- 文本和图片生成节点的默认主节点尺寸统一为 `520 × 260`；浮动控件不得反向改变主节点基础尺寸。
- 双击画布或从图片节点的关联操作入口均创建“图片生成”节点；从现有图片创建时自动建立连线并将该图片选为参考。
- 图片生成节点的输入控件顶部提供参考图片区；输入独立的 `@` 或点击“+”打开参考选择器，选择器支持搜索当前已连接的图片节点和多选。
- 参考选择器默认关闭，选择或重新选择节点不得自动展开；只有新的 `@` 输入或用户点击“+”才触发打开。
- 从选择器选中一张参考图片后立即关闭面板；已选引用名称最多显示 10 个字符，超出部分使用 `...`，完整名称保留在悬停提示中。
- 连线图片只作为候选，不自动全部提交；用户明确选中的图片显示为顶部缩略图及引用标签，支持从缩略图取消引用。
- 已选参考集合必须持久化，并与实际模型请求完全一致；图片生成最多接收 8 张参考图，断开连线后立即从候选、已选区和下一次请求中移除。
- 图片生成节点完成后仍保留“生成”任务身份，再次提交时继续按当前已选参考集合生成。
- 普通图片和图片生成节点均支持双击节点标题重命名；重命名期间隐藏节点的其他浮动控件，生成完成后不得用默认名称覆盖用户标题。
- 生成结果覆盖节点内部的上次结果，不创建额外结果节点；重新生成期间保留旧图，成功后再原位替换。
- 图片生成或编辑任务开始后在节点右上角显示实时耗时；成功后记录并持久化最终耗时，刷新画布后仍可查看。
- 图片结果上传完成后必须立即提交包含结果引用的画布快照，不能只依赖定时自动保存；避免刷新发生在文件落盘与节点保存之间时形成孤立结果。
- 页面刷新或应用重启后，快照中遗留的 `editing` 状态必须转为可重新提交的失败状态，不能继续伪装为正在执行。
- 输入图片由上游图片节点连线提供，连接点位于结果框中点。
- 图片节点的输入、输出和操作连接点必须相对实际图片框垂直居中，不能把图片上方标题高度计入中心位置。
- 图片生成与编辑请求必须使用已启用且包含“图片”模态的模型；当前支持 OpenRouter 图片模型和 ChatGPT GPT-5.6 Sol。
- GPT-5.6 Sol 通过 ChatGPT OAuth Responses 路线调用托管的 `image_generation` 工具：没有参考图时执行纯生成；存在参考图时进入参考图处理模式。
- 无参考图时系统提示词要求按描述创建图片；有参考图时根据用户指令在精确编辑和基于参考重新生成之间判断，多张参考图可分别用于主体、造型、风格、场景或构图。

## 7. 阅读体系

- 支持 PDF、EPUB、TXT 导入、书籍节点、阅读器节点和阅读工作区。
- 阅读器包含目录、正文与笔记区域，记录当前位置、缩放、标注和笔记。
- 阅读器最小化后重新打开必须恢复当前位置并滚动到当前目录项。
- 笔记可以生成画布文本节点，并继续参与节点上下文与 AI 对话。
- OCR 支持本地 Tesseract；外部 OCR 仅在用户显式配置时调用。

## 8. 模型配置

- 服务商配置包含名称、地址、API 格式、认证方式、密钥和启用状态。
- 模型配置包含真实模型 ID、可选别名、上下文窗口、模态和启用状态。
- 服务商和模型不存在全局“默认”状态；节点按用户当前选择或该模态上次使用记录决定模型，并由模型 ID 定位所属服务商。
- 模态包括文本、视觉、图片、向量、音频、排序和工具；节点只显示与自身能力匹配的启用模型。
- Zhipu 由用户手动拉取模型后选择添加；OpenRouter 不依赖全量拉取，可手动维护模型。
- 不设置服务商级或全局默认模型；`isDefault`、`modelMapping` 仅作为旧设置兼容字段，界面不提供“设为默认”。
- 文本与图片分别记录最近一次模型选择；新节点沿用同类节点偏好，模型失效时进入未选择状态并要求用户确认，不静默切换服务商。
- 图片类节点记录最近一次使用的模型、宽高比和画质；新建图片生成节点及普通图片的生成控件沿用最近一次组合，已有节点仍以自身保存的配置为准。
- 文本和图片请求均按模型所属服务商协议分派；图片节点可在 OpenRouter 图片模型与 ChatGPT GPT-5.6 Sol 之间选择。
- ChatGPT 作为内置服务商提供，不使用 API Key 表单，也不可按普通自定义服务商删除。
- 用户点击“登录 ChatGPT”后，应用通过系统浏览器完成 OpenAI OAuth PKCE 登录；本机临时回调仅监听 `localhost:1455/auth/callback`，登录成功后自动拉取该账号可用的 Codex 模型。
- ChatGPT 模型列表来自账号模型接口并支持手动重新同步；同步结果进入统一模型配置，文本节点只显示启用且包含“文本”模态的模型。
- ChatGPT 模型同步使用经过验证的 Codex 协议兼容版本，服务端返回结果仍按账号套餐和 `minimal_client_version` 决定；`visibility=hide` 的内部模型不展示给用户。
- 当前兼容声明版本保留为 `0.150.0`；它是经远程接口实测的协议声明值，不代表公开 Codex CLI 发布版本，也不是从本机 Codex 后端自动读取。版本来源、2026-07-14 复测结果和后续维护流程见 [`docs/api/chatgpt-codex-model-version-maintenance.md`](api/chatgpt-codex-model-version-maintenance.md)。
- ChatGPT access token、refresh token 仅保存在本地数据目录的私有令牌文件中，不进入前端状态、设置 JSON、日志或本地备份；访问令牌临近过期时自动刷新，退出登录后立即删除。
- ChatGPT OAuth、模型同步和 Responses 请求应遵循本机 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` 与 `NO_PROXY`，保证浏览器授权和服务端交换使用一致的网络出口；代理地址不进入前端或日志。
- ChatGPT 文本调用使用 Zenme 自有系统提示词和 OpenAI Codex Responses 路线，不复用 Claude Code 的系统提示词。
- 保存服务商设置后弹窗保持打开并显示保存状态。

## 9. 备份与恢复

- 设置页支持下载 ZIP 备份和恢复本地备份。
- 备份排除模型 API Key。
- 恢复限制压缩包大小、条目数与解压总量，拒绝绝对路径、盘符和路径穿越。
- 恢复必须先在临时目录完整验证，再原子切换；失败时自动回滚原数据目录。

## 10. Token 用量

- 设置页提供“Token 用量”视图，数据只保存在本地数据目录，不依赖云端账户或远程数据库。
- 统计内容包括累计 Token、单日峰值、最长生成耗时、当前/最长连续活跃天数、调用总数和文本/图片调用次数。
- 活动趋势支持每日热力图、每周汇总和累计视图，并展示最常用模型及服务商排行。
- Token 数仅采用服务商响应中明确返回的 usage 数据；服务商未返回用量时记录调用与耗时，但 Token 数保持为零，不在客户端估算。
- 统计从功能启用后的模型调用开始积累，不伪造或反推此前的历史数据。
- 用量记录只包含数量、模型、服务商、模态、时间和耗时，不保存提示词、生成内容、API Key 或 OAuth Token。

## 11. 非功能要求

- 设计遵循 [design-standard.md](design-standard.md)。
- 节点必须保持明确的悬浮阴影，与无限画布形成稳定的纵深关系；缩放画布后也不能因样式失效而完全失去阴影。
- 阴影必须通过设计标准定义的全局语义令牌和语义类实现，语义类直接设置 `box-shadow`；禁止使用会被 Tailwind 误判为阴影颜色的 `shadow-[var(--shadow-*)]` 写法。
- 阴影相关改动的验收必须检查编译后的 CSS 或运行时计算样式，不能仅依据源码中存在阴影类名判断功能已生效。
- 生产构建、单元测试和 ESLint 是里程碑质量门禁。
- 桌面目录包必须能生成并完成冷启动检查。
- 不在日志、接口错误、备份或文档中泄露模型密钥及本机绝对业务路径。

## 12. 当前不包含

- 多用户、账号体系、在线协作、远程数据库和自动云同步。
- 移动端适配与浏览器公网部署。
- 未实现协议的模型能力；设置项不得承诺实际适配器不支持的调用。

## 14. 音乐节点、播放器节点与歌词节点

### 14.1 节点职责

- 上传本地音频文件时，系统应根据文件内容、容器和 MIME 类型识别音频，不只依赖扩展名；识别成功后创建音乐节点。
- 音乐节点是可复用的本地音频资产节点，保存文件引用、标题、艺术家、专辑、封面、时长、容器、编码、采样率、声道、比特率和波形产物引用，不在节点内部维护独立播放引擎。
- 播放器节点通过连线引用一个音乐节点，提供播放、暂停、停止、进度跳转、音量、静音、倍速、循环、当前时间和总时长等常规控制。
- 播放器节点显示音乐基础信息、封面和波形；后续可在统一时间轴上叠加歌词、段落、和弦、节拍和分析标记。
- 音乐资产、播放器及所有音乐分析结果节点采用统一外置可编辑标题、语义节点阴影、固定主框尺寸和居中连接端点；动态状态与长内容不得撑大主框。
- 音乐工作流采用固定主干：`音乐节点 → 播放器节点 → 分析类子节点`。音乐节点只连接播放器节点，不直接连接歌词、综合分析或 Suno 提示词等分析类节点。
- 音乐节点本体不显示“创建播放器”按钮。用户从节点右侧拉出连线并在画布空白处松开后，通过连线菜单选择“创建播放器”；播放器应创建在松开位置。已有播放器时不得重复创建。
- 播放器节点只负责播放控制、波形和共享时间轴，不承载完整分析任务，不显示分析进度、分析错误或分析完成状态。
- “歌词与结构”“综合分析”“Suno 提示词”及后续分析动作统一放入从播放器右侧拉线后出现的菜单；用户选择任一动作后必须立即在松开位置创建对应节点，由新节点展示自身的排队、执行、失败、重试和结果状态。
- 音乐分析结果节点在排队、准备和执行阶段持续显示已运行时间；任务结束后显示服务端记录的总耗时。开始、结束与耗时随 `jobId` 持久化，刷新画布后仍可查看。
- 任务耗时以音乐分析服务返回的 `startedAt`、`completedAt`、`elapsedMs` 和 `durationMs` 为准；前端只在两次状态更新之间按本地时钟补帧，不得覆盖服务端最终值。
- 目标明确的分析任务必须在正式推理前校验核心能力。歌词节点缺少歌词识别能力时应快速失败并说明缺少的模型，不得耗时执行其他分析后将空歌词伪装为成功。
- 歌词、综合分析、Suno 提示词及后续和弦、结构等分析节点均为播放器的下游子节点；它们通过播放器共享音乐来源和统一时间轴，但各自持有与自身能力范围对应的任务引用，不复制音频文件。
- 分析节点按需请求能力，不得以创建任一结果节点为由强制执行全部分析：歌词节点请求歌词、结构及其必要依赖；综合分析节点请求所展示的音乐特征；Suno 提示词节点请求生成提示词所需的最小依赖集合。
- Suno 提示词任务启动前检查同一音频、分析器版本和参数下的已有分析产物；已有能力直接使用缓存，只补齐缺失依赖，全部依赖满足后再生成提示词。
- “子节点”表示画布图谱中的有向父子关系和连线来源，不要求使用 React Flow 的容器嵌套或限制子节点只能在播放器边界内移动。
- 播放器节点的播放状态不得写回音乐资源本身；分析子节点的高频联动状态也不得持续写入画布快照。
- 播放器没有有效上游音乐节点时显示空状态；断开或替换连线后立即停止旧音频并切换数据源。
- Zenme 的音乐能力以音乐理解、分析结果展示和生成 Suno 提示词为核心；多轨剪辑、混音、效果器和 DAW 工作区不属于当前核心范围。

### 14.2 播放与性能

- 应用使用全局音频会话统一管理播放器，默认同一时间只允许一个播放器发声；启动新的播放器时暂停当前播放器。
- 播放进度、缓冲状态等高频状态只保存在运行时，不得随每次时间更新触发画布快照保存；是否持久化上次播放位置作为后续产品选项。
- 音频通过受限于本地数据目录的 loopback 同源接口读取，接口必须支持 HTTP Range、`206 Partial Content`、正确的媒体类型和内容长度，以支持大文件流式播放与任意位置跳转。
- 不得在 Electron 渲染进程中为长音频解码完整 PCM；波形优先使用服务端预计算的 RMS 响度包络，并按音频哈希、生成器版本和分辨率缓存。
- 播放器不得使用占位算法伪造波形。音乐节点连接播放器后，自动提交仅包含 `metadata + waveform` 的轻量任务；收到预计算包络后立即绘制并缓存，不等待用户发起完整音乐分析。
- 波形必须覆盖完整歌曲时间轴，并使用全曲一致的稳健归一化；播放器与综合分析节点共用同一前端降采样规则，禁止使用长窗口瞬时最大值造成波形平顶失真。
- 轻量波形任务与完整分析任务相互独立，不写入完整分析的任务状态，也不启用歌词与结构、综合分析或 Suno 提示词结果节点。
- 首选 `WaveSurfer.js v7` 实现单轨播放、波形、时间尺和结构区段；不得为当前需求引入多轨编辑内核。
- 元数据优先使用 `music-metadata` 在本地服务端读取，容器与编码信息可由 `ffprobe` 复核；Chromium 不能直接播放的格式应生成播放代理文件，不修改原始音频。

### 14.3 歌词与音乐结构节点

- 用户从播放器拉线并选择“歌词与结构”时立即创建一个以播放器为上游的歌词节点；歌词识别和结构分析在该节点内执行，不在播放器内部嵌入任务或完整歌词面板。
- 同一播放器默认只关联一个主歌词节点；再次使用入口时定位并展开已有节点，避免重复创建相同分析结果。
- 歌词节点展示音乐分析服务返回的逐行歌词和起止时间，同时展示 Intro、Verse、Pre-Chorus、Chorus、Bridge、Instrumental、Outro 等结构区段。
- 歌词正文与结构分段必须限制在固定节点主框内滚动，不得越过节点边框；节点内部不显示“来自播放器的时间戳歌词”、定位图标或“分析完成/用时”成功状态行。
- 歌词任务耗时显示在节点主框外侧右上角，采用紧凑单位，例如 `58s`、`1m 2s`；刷新画布后仍使用服务端最终耗时。
- 歌词来源按“可信同步曲库优先、Whisper 转写后备”的顺序选择。曲库候选只通过标题、歌手与时长联合校验和排序；专辑名、专辑版本和专辑相似度不参与歌曲身份判断，仅作为结果元数据显示。只有曲库未返回可信同步歌词时才回退到 Whisper，结果中必须保留来源与模型版本以便诊断。
- 结构区段允许没有歌词，例如前奏、间奏和尾奏；歌词行必须归属对应结构区段或明确标记为未归类。
- 播放器波形、歌词节点和结构区段共享同一秒制时间轴。播放时自动高亮当前结构和歌词行，并将当前歌词滚动到可视区域；点击歌词行或结构标题时播放器跳转到对应起始时间。
- 歌词节点既是可阅读的分析结果，也是可连接的结构化上下文，可继续连接文本节点或 Suno 提示词节点。
- 分析结果必须保留原始识别文本、用户修订文本、时间戳、语言、来源分析器、模型版本和置信度；用户修订不得被重新分析结果静默覆盖。
- 歌曲结构的模型来源、内部置信度和融合评分属于诊断数据，不在终端节点中展示“模型预测结构”、高/中/低置信度或类似技术标签；终端也不提供结构标签与段落边界的手工编辑功能。
- 结构识别质量在音乐分析服务内部改进。候选方案是融合时间戳歌词的重复关系、节拍与小节边界、能量变化及旋律重复特征，对结构模型给出的候选边界和标签重新评分；该方案进入验证阶段后才能替换现有结果，不得由前端使用启发式规则伪造结构。
- 尚未完成歌词或结构分析时，节点显示对应任务状态、阶段进度和可重试错误，不伪造空歌词为成功结果。
- 综合分析节点和 Suno 提示词节点遵循相同按需创建规则。一次拉线操作只创建一个节点；同一节点重试时复用原任务与缓存，不因重试额外创建节点。
- Suno 提示词节点默认尺寸为 `520 × 360px`，支持用户拖拽调整且保存调整结果，最小尺寸为 `420 × 280px`；中英文提示词内容必须在节点剩余空间内滚动，不得越过节点边框。
- 综合分析节点默认尺寸为 `620 × 720px`，支持用户拖拽调整且保存调整结果，最小尺寸为 `480 × 420px`；指标、波形、结构时间轴和完整报告必须在主框内部布局或滚动。

### 14.4 待确认问题

- 首版支持的格式范围，以及对 FLAC、ALAC、APE、DSD 等格式采用直接播放、代理转码还是明确不支持。
- 播放器是否需要 A-B 循环、波形缩放、键盘快捷键、系统媒体键及播放位置持久化。
- 波形峰值由 Zenme Local 的轻量本地任务生成，还是统一交给独立音乐分析服务生成。
- 歌词节点是同时显示结构导航和歌词正文，还是提供“结构/歌词”两个视图；首版建议在同一纵向时间线上分组展示。
- 是否允许直接在歌词节点校正歌词文本和时间戳，以及修订后如何与重新分析结果合并；本问题不包含结构标签和段落边界编辑。

## 15. 本地音乐分析服务

### 15.0 API-first 接入决策

- 统一的外部能力产品模型、安全边界和技术合同见 [《外部能力对接与产品规范》](external-capability-integration-spec.md)。
- `zenme-music-service` 是独立安装、独立运行、独立版本化的本地组件，不进入 Zenme 渲染进程和代码包。
- Zenme 默认通过只监听 loopback 的版本化 HTTP API 连接该组件；服务进程由独立组件自行启动和维护，Next.js 请求生命周期不得隐式创建服务进程。
- 长任务使用持久 `jobId`，支持查询、取消、重试，以及断线或应用重启后的恢复；当前不依赖实验性 MCP Tasks。
- MCP stdio 仅作为显式启用的可选集成与自动化入口，不是桌面应用默认传输；MCP 与 HTTP 必须复用同一分析核心和任务存储。
- 画布 schema v3 将旧音乐节点上的任务状态迁移至唯一播放器节点，并把旧分析节点重新挂接到播放器。

### 15.1 产品目标

- 用户上传音乐后，可获得歌词与时间戳、歌曲结构与段落、基础音乐信息、风格、情绪、乐器、和弦、人声声学特征，并生成适用于 Suno 的结构化提示词。
- 音乐分析默认支持完全本地运行；云端音乐 API 只能作为用户主动配置的可选供应商、结果复核或本地能力降级路线。
- 唱腔等尚无成熟通用模型的能力必须标记为实验性推断并显示置信度，不得作为确定事实展示。

### 15.2 架构决策

- 音乐分析必须由独立本地服务承载，不得在 Electron 渲染进程、Next.js Route Handler 或桌面主进程中直接加载 PyTorch、CUDA 模型或执行长时间音频任务。
- Zenme 负责上传入口、任务创建、进度展示、取消与重试、分析结果节点、时间轴交互和 Suno 提示词展示。
- Zenme 通过 `/v1/capabilities` 协商 `player-preview`、`lyrics-structure`、`comprehensive-analysis` 和 `suno-prompt` 产品 profile；新服务负责展开内部 DAG，Zenme 不请求内部阶段。旧服务未公布 profile 或探测失败时，回退到 `complete` 与旧显式能力列表。
- 音乐服务负责 FFmpeg 标准化、模型与运行时安装、GPU 队列、推理、阶段缓存、中间文件、结果聚合和模型版本记录。
- 服务仅监听本机回环地址并使用高熵会话令牌认证；独立组件自行负责启动、升级与退出，Zenme 只配置连接、执行健康检查并在断开后停止轮询，不隐式终止服务任务。
- 服务采用能力适配器架构。Demucs、Whisper、All-In-One、Essentia、和弦识别器、Basic Pitch 和本地 LLM 均为可替换适配器，不允许业务流程直接依赖单一项目的输出格式。
- 对已有成熟开源实现的音频分析能力优先集成，不自行实现分轨、语音识别、结构分析、和弦识别或音频转 MIDI 核心模型。

### 15.3 首版分析流程

1. 读取文件元数据，计算内容哈希并建立任务。
2. 使用 FFmpeg 生成统一时间轴的分析音频、语音音频和波形数据。
3. 执行基础特征分析与 GPU 分轨。
4. 对人声轨执行歌词转录与人声声学特征分析。
5. 对完整音频和分轨结果执行段落、节拍、风格、情绪、乐器、和弦及音符分析。
6. 将各分析器结果归一化为统一时间轴和统一结果结构，保留来源、模型版本与置信度。
7. 根据结构化结果生成音乐报告及 Suno 提示词；修改提示词模板不得触发音频重新分析。

### 15.4 任务与缓存

- 任务状态统一为 `queued`、`preparing`、`running`、`succeeded`、`failed`、`cancelled`。
- 服务按分析阶段报告进度和当前适配器，支持取消、失败重试与应用重启后的任务恢复。
- 缓存键至少包含音频 SHA-256、分析器 ID、模型版本和参数版本；同一音频只重跑受配置变化影响的阶段。
- GPU 阶段默认串行执行；只有适配器声明可安全并发且显存预算允许时才并行，避免多模型争用 RTX 4090 显存。
- 原始音频、分轨、中间结果和最终分析结果均保存在用户本地数据目录，并提供可配置的缓存清理策略。

### 15.5 质量与合规

- 每个输出字段必须携带分析器来源、模型版本、置信度或“未提供置信度”状态。
- 冲突结果不得静默覆盖；聚合层应保留原始候选并记录最终选择规则。
- 模型安装前必须展示下载大小、运行要求和许可证；非商业或传染性许可证模型不得无提示随商业发行包分发。
- 服务日志不得记录完整歌词、用户音频、模型密钥或外部 API 密钥。
- 在不改变本地数据所有权的前提下评估可选加密密钥存储。

## 16. 外部能力接入

- Zenme 以“服务商、能力、操作、任务、产物”为统一对象模型；节点面向产品能力，不暴露第三方服务的内部执行阶段。
- 独立本地服务默认通过版本化 loopback HTTP API 接入；MCP 仅作为用户显式启用的自动化入口，不能成为静默降级通道。
- 渲染器仅调用 Zenme 同源接口，不保存密钥、不拼接外部服务 URL，也不直接访问模型供应商或独立服务。
- 长任务必须创建可恢复的持久任务，并由下游结果节点展示排队、执行、成功、失败、取消、重试和耗时状态。
- 本地执行与远程执行必须在设置页明确标识；向远程服务发送文件或内容前，必须让用户能够识别处理位置和数据范围。
- 外部组件必须提供能力发现和协议版本信息；不兼容时应显示“需要升级”，不得以模糊的网络错误替代。
- 密钥、访问令牌和敏感路径只保存在本地受控配置中，不进入前端状态、日志、文档、备份或仓库。
- 完整产品交互、通用协议、错误模型、安全要求及验收清单以 [《外部能力对接与产品规范》](external-capability-integration-spec.md) 为准。
