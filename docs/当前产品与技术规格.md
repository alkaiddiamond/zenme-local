# Zenme 当前产品与技术规格

更新时间：2026-06-27

本文档用于汇总 Zenme 当前已经确认并阶段性实现的产品需求、交互规则和技术实现细节。更细的专题文档仍保留在：

- `docs/prd.md`：主 PRD 与阶段性变更记录。
- `docs/阅读体系需求文档.md`：阅读体系专项需求。
- `docs/无限画布性能优化调研报告.md`：性能问题分析、观测与优化记录。
- `docs/api/`：模型 API 与外部接口资料。

## 1. 产品定位

Zenme 是一个面向独立创作者和研究者的 AI 项目工作空间。产品核心不是单一聊天框、文件夹或白板，而是围绕“项目”组织资料、节点、阅读、生成、笔记和 AI 上下文。

当前核心形态：

- Dashboard 首页：创建项目、查看最近项目、进入项目画布。
- 无限画布：承载资料、文本、图片、书籍、阅读器、笔记、AI 生成节点和节点关系。
- 阅读体系：将 PDF、EPUB、TXT 等资料变成可阅读、可标注、可引用、可生成节点的项目材料。
- AI 节点体系：文本节点作为上下文，文本生成节点保存 prompt，AI 回复节点保存只读回答。

## 2. 视觉与交互原则

- 当前主视觉采用白色点阵画布、轻量边框、细阴影、克制灰阶和少量强调色。
- 节点、菜单、阅读器、笔记栏、缩略图和浮动工具条应尽量复用 Zenme 当前组件风格。
- 复杂能力应以画布节点存在，而不是脱离画布的模态窗口。
- 画布缩放统一使用 `Ctrl + 鼠标滚轮`；普通滚轮在阅读器、文本节点、AI 回复节点内部优先滚动对应内容。
- 鼠标中键拖动始终移动画布，即使鼠标位于阅读器内部。
- 具有编辑语义的区域应显示文本光标；只有拖动手柄、标题图标、工具按钮才显示手型。

## 3. Dashboard 与项目

### 3.1 首页能力

- 首页支持新建项目。
- 最近项目按照上次打开时间排序。
- 项目卡片使用 16:10 缩略图比例。
- 缩略图只展示画布节点内容，不应包含左侧 sidebar、小地图、控制条、React Flow attribution 等固定 UI。
- 快速进出项目时，缩略图允许稍后刷新，不要求每次退出立即同步生成。

### 3.2 项目状态

- 项目保存状态显示在画布左上角。
- 项目名称可在画布左上角点击编辑。
- 退出画布再进入时，应恢复上次关闭时的画布 viewport。

## 4. 无限画布

### 4.1 基础能力

- 画布基于 `@xyflow/react` / React Flow 实现。
- 前端维护 `nodes`、`edges`、`viewport` 三类核心状态。
- 画布支持拖拽节点、连线、缩放、平移、框选、多选、节点 resize、撤销/重做和保存。
- 节点重叠时，点击目标节点应提升该节点层级，避免被上方节点长期遮挡。

### 4.2 节点端点与连线

- 节点左右白色连线端点与边关系相关：
  - 有入边时显示左侧端点。
  - 有出边时显示右侧端点。
  - 没有任何连线时左右端点都不显示。
- React Flow handle 仍需保留渲染，只在视觉上隐藏无连接端点，避免自动创建节点后连线不可见。
- 手动从节点加号拖线创建节点时，新节点位置应使用拖线终点。
- 自动生成子节点时，可使用“追加到最新子节点下方”的布局规则，避免覆盖已有子节点。
- 自动生成节点后，连线必须立即可见，不应依赖刷新页面。

### 4.3 节点类型

当前 `CanvasNodeData.kind` 支持：

- `image`：图片节点。
- `file`：普通文件节点。
- `text`：富文本节点。
- `textGeneration`：文本生成节点。
- `agent`：AI 回复或 Agent 输出节点。
- `book`：书籍节点。
- `reader`：阅读器节点。
- `note`：阅读笔记节点。
- `group`：分组框节点。

### 4.4 分组

- 多选 2 个及以上未分组节点后，可执行“打组”。
- 分组生成透明组框，标题在框外。
- 选中组框时边框与普通节点选中态保持一致。
- 移动组框时，组内节点跟随移动。
- 组内节点允许拖出组框，拖出后解除分组关系。
- 点击组内节点时，组框不能阻挡内部节点选择。

## 5. 文本与 AI 节点体系

### 5.1 文本节点

文本节点是纯富文本编辑器和上下文来源，不再在聚焦后弹出 AI 提问框。

已确认能力：

- 默认标题为“文本”，不会随正文内容自动变化。
- 双击标题文字进入标题编辑。
- 标题左侧图标区域作为拖动手柄。
- 内容区点击即可编辑。
- 空内容且未聚焦时显示 placeholder：`点击此处编辑文本`。
- 聚焦后 placeholder 隐藏；失焦且内容仍为空时重新显示。
- 支持四边和四角 resize，尺寸持久化。
- 支持 Bold、Italic、Underline、inline code。
- 工具栏支持将选中文本创建为该文本节点的子节点。
- 失焦后清除文本选区高亮。
- 内容滚动条不应超出节点圆角，不显示浏览器默认上下三角按钮。

### 5.2 文本生成节点

文本生成节点通过节点加号拖线菜单创建，用于保存一次 AI 生成请求的 prompt 和模型选择。

已确认能力：

- 节点类型为 `textGeneration`。
- UI 类似输入框组件，但作为独立画布节点存在。
- 可编辑 prompt，可选择模型，可重新提交。
- 提交后生成一个 AI 回复子节点。
- 重新提交不覆盖旧回复，而是生成新的回复节点。
- 支持 resize 和持久化。
- 可沿入边读取父节点和祖先节点上下文，不引入兄弟节点。

### 5.3 AI 回复节点

AI 回复节点用于展示生成结果。

已确认能力：

- 节点类型复用 `agent`。
- 内容只读，不直接编辑。
- 不再保存或展示“提问”“回答”等额外标签。
- 若结果不满意，应回到父级文本生成节点修改 prompt 后重新生成。
- 内部内容区域使用浅灰只读面板，与可编辑文本节点区分。
- 支持 resize。
- 鼠标滚轮悬停在内容区时，应滚动回复内容。

### 5.4 AI 上下文规则

当前上下文组织方向：

- 文本节点提供标题与纯文本内容。
- AI 回复节点提供标题与回复内容。
- 阅读笔记节点提供来源书籍、原文、备注和定位信息。
- 图书节点提供书籍标题和文件名。
- 文本生成节点可沿入边向父节点、祖先节点追溯上下文。
- 不自动引入兄弟节点。
- 并非所有节点类型都默认支持作为上下文，后续需要按节点类型显式开放。

## 6. 阅读体系

### 6.1 产品形态

阅读体系不是从 Inkcode 迁移，而是在 Zenme 画布体系中重新实现 Inkcode 已验证的阅读能力。

核心链路：

1. 用户将 PDF、EPUB、TXT 拖入画布。
2. 系统创建 `book` 书籍节点。
3. 用户从书籍节点加号拖线，选择“在阅读器中打开”。
4. 系统创建 `reader` 阅读器节点，并连接书籍节点和阅读器节点。
5. 用户在阅读器中阅读、标注、记录笔记。
6. 笔记可生成画布节点，并参与后续 AI 对话或节点组织。

### 6.2 书籍节点

- 节点文案显示为“书籍”。
- 默认图标使用合上的书。
- 优先使用识别到的书籍封面：
  - PDF 可使用首页渲染图。
  - EPUB 优先读取包内封面。
  - TXT 无封面时保留默认书本图标。
- 书籍节点不通过双击打开阅读器，只通过加号菜单打开。

### 6.3 阅读器节点

- 阅读器是画布内节点，不是模态窗或全屏覆盖层。
- 节点文案显示为“阅读器”，图标使用打开的书。
- 支持移动、resize、折叠和展开。
- 折叠时尺寸与普通书籍节点接近，并标明对应书籍和阅读器身份。
- 折叠阅读器时，从该阅读器连接出去的子节点和子连线同步隐藏；展开后恢复。
- 阅读器只支持滚动阅读模式；单页/翻页模式不进入当前版本。
- 阅读器内部三栏布局：
  - 左侧目录。
  - 中间阅读内容。
  - 右侧笔记。

### 6.4 阅读进度与内容缩放

- PDF、EPUB、TXT 阅读器需要记录阅读进度。
- PDF 和 EPUB 支持内容缩放控件，缩放只作用于阅读内容，不改变画布 zoom，也不改变阅读器节点外框尺寸。
- 阅读状态按 `assetId` 隔离，避免同一画布中多本书互相覆盖进度。
- 当前阅读状态包含：
  - `sectionIndex`
  - `contentScale`
  - `scrollRatio`
  - `updatedAt`
- 前端用 `localStorage` 建立每本书的快速缓存，服务端通过 Supabase `reading_progress` 持久化；加载时优先用本地缓存避免刷新后先渲染 100% 再跳变。

### 6.5 PDF 阅读

- PDF 使用 PDF.js 渲染。
- 文本型 PDF 渲染 text layer，鼠标在正文区域应显示 I 形文本选择光标。
- 图片型 PDF 使用区域框选和 OCR 识别。
- PDF 页面快速缩放时，需要取消或串行化同一 canvas 上未完成的 render task，避免 `Cannot use the same canvas during multiple render() operations`。
- 长文档目录跳转需要按页高估算并修正滚动位置，避免点击最后页需要多次才到达。
- Header 应固定在阅读器内部顶部，目录跳转或内容滚动不应把 header 顶走。

### 6.6 EPUB 阅读

- EPUB 参考 Inkcode 滚动模式做分页。
- 正文内容区采用固定版心宽度，调整阅读器外框大小不改变 EPUB 正文排版宽度。
- 识别为中文内容时，正文段落首行缩进两个字。
- 默认段落间距为 `1.5em`；100% 缩放下，16px 字号对应约 24px 段后距。
- EPUB 与 PDF 在 100% 内容缩放时使用一致的默认视觉宽度基准。
- EPUB 页面分割线与章节页码保留，并与 PDF 页码边距尽量统一。

### 6.7 TXT 阅读

- TXT 作为基础文本阅读格式支持。
- 文本内容可用于选择、标注和笔记。

### 6.8 标注与笔记

通用规则：

- 选中文字或框选区域后显示浮动标注控件。
- 点击颜色即创建对应颜色标注，不再额外点击“标注”按钮。
- 新标注追加到右侧笔记列表底部，并滚动到底部。
- 笔记列表按用户排序保存；默认顺序为创建时间从旧到新。
- 笔记卡片显示完整时间，格式包含年月日时分秒。
- 点击笔记卡片应快速跳转到原文位置。
- 同一笔记允许创建多个画布节点。

PDF 图片型区域标注规则：

- 框选后先显示灰色区域框。
- OCR 完成后，将识别文字显示到右侧临时编辑区域。
- 用户点击颜色后才正式创建标注和笔记卡片。
- 框选区域可拖动调整位置，也可拖动边界调整范围；停止调整后重新 OCR。
- 如果 OCR 失败或超时，应显示可理解的错误状态，不能无限停留在“识别中”。

### 6.9 笔记生成画布节点

- 右侧笔记卡片提供图标按钮：
  - 创建画布节点。
  - 编辑。
  - 复制。
  - 删除。
- 六点拖拽手柄只用于排序，不用于创建节点。
- 从笔记创建的画布节点应连接阅读器节点，而不是书籍节点。
- 自动创建的笔记节点应按阅读器已有子节点位置追加排列。

## 7. OCR

### 7.1 当前策略

OCR 用于图片型 PDF 区域标注。当前通过服务端接口 `/api/reading/ocr` 调用，前端不直接持有第三方密钥。

支持 provider：

- `local-model`：开发和默认方案，使用 `tesseract.js` 本地识别。
- `tencent`：腾讯云 OCR 技术验证方案，需要通过环境变量配置密钥。

### 7.2 本地 OCR

当前本地 OCR 实现：

- 语言：`chi_sim + eng`。
- 运行库：`tesseract.js`。
- 语言包来源：`@tesseract.js-data/chi_sim`、`@tesseract.js-data/eng`。
- 模型目录：`data/ocr-models/tessdata`。
- 缓存目录：`data/ocr-models/tesseract-cache-v2`。
- 首次识别时懒加载 worker，会话级复用。
- 后处理会去除 CJK 字符之间多余空格。

`data/ocr-models/` 不提交到 Git。

### 7.3 腾讯云 OCR

腾讯云 OCR 只作为可选 provider。密钥必须放在环境变量中，不能写入前端代码、文档或仓库。

相关环境变量：

- `READING_OCR_PROVIDER=tencent`
- `TENCENT_CLOUD_SECRET_ID`
- `TENCENT_CLOUD_SECRET_KEY`

## 8. 数据模型与存储

### 8.1 画布快照

画布快照结构：

```ts
type CanvasSnapshot = {
  version: 1;
  nodes: CanvasNode[];
  edges: Edge[];
  viewport: { x: number; y: number; zoom: number };
  updatedAt: string;
};
```

保存策略：

- 画布快照保存到 Supabase。
- 缩略图上传到 Supabase Storage。
- 当前不再保留本地项目模式和本地画布快照读写路径。

### 8.2 阅读数据

阅读数据已切换到 Supabase 表和 Supabase Storage：

- 原始阅读文件路径：`{user_id}/{project_id}/reading/original/{asset_id}.{ext}`；Storage key 不拼接原始文件名，避免中文书名或特殊字符触发对象存储 `Invalid key`。
- 原始文件名保存在 `reading_assets.file_name`，用于界面展示和下载响应头。
- 封面路径：`{user_id}/{project_id}/reading/covers/{asset_id}.{ext}`
- 访问控制：所有阅读表按 `owner_id = auth.uid()` 做 RLS，Storage 沿用路径首段用户 ID 隔离。
- 上传限制：阅读资料最大 `50MB`，与 `project-assets` Storage bucket 上限一致；超过 `8MB` 时客户端使用 binary 上传路径，服务端仍按统一上限校验。
- HTML 清洗：EPUB/阅读 HTML 渲染前通过 `sanitizeReadingHtml()` 移除脚本、嵌入标签、事件属性和危险 URL。
- TXT 解析：纯文本章节拆分已抽到 `parseTxtSections()`，按中文章节标题拆分、统一换行并对文本生成的 HTML 做转义。

当前表：

`reading_assets`

- `id`
- `owner_id`
- `project_id`
- `node_id`
- `title`
- `author`
- `format`
- `file_name`
- `storage_path`
- `cover_path`
- `mime_type`
- `size_bytes`
- `created_at`
- `updated_at`

`reading_notes`

- `id`
- `asset_id`
- `owner_id`
- `project_id`
- `selected_text`
- `comment`
- `section_index`
- `chapter_title`
- `color`
- `type`
- `offset`
- `length`
- `rect`
- `sort_order`
- `created_at`
- `updated_at`

`reading_progress`

- `asset_id`
- `owner_id`
- `project_id`
- `section_index`
- `content_scale`
- `scroll_ratio`
- `updated_at`

UI 和阅读器组件不直接依赖 Supabase SDK；阅读数据通过 `/api/reading/**` 和 `lib/reading/supabase-repository.ts` 隔离。

## 9. API

### 9.1 AI

- `POST /api/ai/chat`：调用模型生成回复。
- `GET /api/ai/models`：获取可用模型列表。

### 9.2 阅读

- `POST /api/reading/assets`：登记阅读资料。
- `GET /api/reading/assets/[assetId]`：读取阅读 payload。
- `GET /api/reading/assets/[assetId]/cover`：读取封面。
- `GET /api/reading/assets/[assetId]/epub-asset`：读取 EPUB 内资源。
- `GET /api/reading/assets/[assetId]/file`：读取原文件。
- `GET/POST /api/reading/assets/[assetId]/notes`：读取或创建笔记。
- `PUT /api/reading/assets/[assetId]/progress`：保存阅读进度和内容缩放。
- `PATCH/DELETE /api/reading/notes/[noteId]`：更新或删除笔记。
- `POST /api/reading/ocr`：图片区域 OCR。

## 10. 性能与可观测性

### 10.1 已建立的观测能力

- `NEXT_PUBLIC_ZENME_PERF_DEBUG=1` 开启性能日志。
- `window.__ZENME_CANVAS_PERF__` 保存最近 100 条性能指标。
- `window.__ZENME_CANVAS_PERF_SUMMARY__()` 汇总性能指标。
- 本地开发环境显式追加 `zenmePerfSeedDebug=1` 后，`zenmePerfSeed` 可生成大画布测试节点。
- `zenmePerfEdgesPerRow` 控制连线密度。
- 本地开发环境显式追加 `zenmePerfSeedDebug=1` 后，`zenmePerfSample=1` 自动采样。
- `zenmePerfSampleThumbnail=1` 追加缩略图采样。

### 10.2 已落地优化

- 保存请求 in-flight 合并，避免多来源重复保存。
- 画布快照保存已收口到 Supabase，避免本地项目模式和云端项目模式并行维护。
- 普通保存不频繁生成缩略图；缩略图在后台、低频或空闲时生成。
- React Flow 开启 `onlyRenderVisibleElements`。
- 节点拖动和 resize 时临时暂停 MiniMap 真实渲染。
- 节点组件和阅读器重组件使用 memo 降低无关重渲染。
- 连线派生从重复 `nodes.find(...)` 改为 Map 查找。
- 阅读器滚动处理使用 `requestAnimationFrame` 合并。
- 阅读进度保存防抖并按 `assetId` 缓存，避免阅读器反复刷新和 PDF 闪渲染。

### 10.3 性能设计原则

- 阅读器作为画布节点的产品形态不应为了性能退回模态窗。
- 复杂节点内部状态应尽量局部化，不要频繁写回画布节点数据。
- 选中态、焦点态、测量态等运行时状态不应触发持久化快照。
- 大文件、PDF 渲染、OCR、缩略图生成都应避免阻塞画布主交互。

## 13. 当前开放问题

- 文本生成节点多父节点和上下文追溯规则需要继续细化哪些节点类型可作为上下文来源。
- 阅读数据 Supabase 表结构、RLS 策略和 Storage 路径已形成首版迁移，并已应用到远端 Supabase `zenme`；端到端烟测步骤已整理到 `/docs/api/supabase-migration-runbook.md`，仍需执行浏览器烟测并记录结果。
- 视频节点可进入画布播放，但需要约束同一时间只允许一个视频播放；该能力尚未进入当前落地范围。
- 大型真实画布下仍需持续采样，尤其是多阅读器、多 PDF、大量笔记和缩略图生成场景。
- 图片型 PDF OCR 在不同扫描质量、倾斜、水印和低分辨率文件上的准确率需要继续验证。
