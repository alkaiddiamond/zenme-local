# Zenme Local 代码审计与处置报告

审计日期：2026-07-10  
原始基线：`a688413`
处置目标：纯本地 0.1.0 里程碑

## 1. 结论

项目已从“本地与远程双模式并存”收敛为纯本地桌面应用。运行时依赖、认证页面、远程仓库、迁移脚本和相关文档均已移除。本轮同时处理了本地 API 暴露、备份恢复、模型适配、节点模型追踪、输入容量和 Electron 导航等问题。

当前主要剩余风险是大型客户端组件的维护成本、真实模型调用缺少自动化端到端覆盖，以及桌面安装升级场景尚需更多人工验证；这些不阻断 0.1.0 本地功能基线。

## 2. 原审计项处置

| 编号 | 原问题 | 处置结果 |
| --- | --- | --- |
| A-01 | 导入包路径逃逸 | 已移除旧迁移导入链路；本地备份恢复统一使用安全路径、条目预算和临时目录校验。 |
| A-02 | 管理接口缺少访问边界 | 已增加统一 loopback、同源和跨站校验；应用服务绑定 `127.0.0.1`。 |
| A-03 | 备份包含明文密钥 | 已默认从备份中的设置移除所有服务商 API Key。 |
| A-04 | 模型拉取 SSRF | 产品已限定为本机单用户；地址仍要求 HTTP(S)，管理 API 不对局域网或公网开放。 |
| A-05 | 图片编辑要求登录 | 账号与认证链路已整体移除，图片编辑采用本地访问边界。 |
| A-06 | API 格式与适配器不一致 | 文本调用按 OpenAI/Zhipu/OpenRouter/Anthropic 分派；图片编辑限制为已实现的 OpenRouter 路线。 |
| A-07 | 节点模型与实际调用不一致 | 请求携带节点模型并由服务端校验，节点保存真实模型和参数。 |
| A-08 | 双数据源混合 | 已彻底移除远程数据模式及相关依赖。 |
| A-09 | 恢复缺少资源限制与事务 | 已增加 200 MB 压缩包、20000 条目、2 GB 解压预算，以及原子切换和回滚。 |
| A-10 | 画布与文件浅校验 | 已增加画布 schema、节点/边数量、缩略图 MIME/大小及文件 50 MB 限制。 |
| A-11 | 无效设置项 | 已移除主题、语言、快照历史、同步开关等无消费者设置；自动保存间隔已接入。 |
| A-12 | 新节点不沿用模型偏好 | 已分别持久化文本与图片最近模型。 |
| A-13 | 历史文本生成入口 | 已移除新建入口，保留旧快照兼容渲染。 |
| A-14 | Electron 跨源导航 | 已限制主窗口 origin、外部协议和权限请求。 |
| A-15 | 核心组件过大 | 已抽出大量画布命令、持久化、上下文和渲染模块；大型协调组件仍列入后续演进。 |
| A-16 | 生产依赖审计项 | 继续跟踪 Next.js 上游；不使用破坏性主版本回退。 |

## 3. 新增质量措施

- 本地访问边界单元测试。
- 画布快照容量与结构验证测试。
- 备份密钥脱敏、路径和恢复行为测试。
- 模型协议、模型偏好和节点模型元数据回归测试。
- 生产构建用于确认不存在已删除页面和服务的残留路由。

## 4. 剩余风险

### P2

- 真实模型服务受密钥、额度和上游协议变化影响，自动化测试默认不发起计费请求。
- 用户密钥目前保存在本地设置文件中，尚未接入操作系统凭据保险库。

### P3

- `canvas-client.tsx`、`settings-client.tsx`、`reading-workspace.tsx` 仍承担较多协调职责。
- 尚未建立 Windows 安装包升级覆盖、超大数据目录和断电恢复的系统测试。

## 5. 里程碑判定

0.1.0 必须满足：ESLint、全部单元测试、Next.js 生产构建和 Electron 目录打包通过；运行时代码与依赖中不存在已移除远程数据服务；文档与本地产品边界一致。
