# Zenme 阅读体系需求文档

## 1. 背景

Zenme 当前是基于 Next.js + Supabase 的 AI 项目画布，用户可以在项目中拖入文件、图片，形成画布节点，并通过节点连接和 Agent 对话推进创作与研究。

用户希望参考 `G:/development/inkcode` 项目中已经验证过的阅读能力，在 Zenme 的项目画布体系中重新实现一套阅读能力，使书籍资料不只是普通文件，而是可以在项目画布内被阅读、标注、摘录、引用，并进一步参与 AI 对话。

本需求文档聚焦“阅读体系”在 Zenme 中的产品形态、核心流程、功能边界、数据建议和待确认问题。

## 2. 产品定位

阅读体系是 Zenme 项目画布中的资料理解能力。

它不是独立书库应用，而是项目工作流的一部分：

- 书籍作为项目资料进入画布。
- 阅读器作为画布内的沉浸式工作界面打开。
- 阅读过程中的笔记、摘录、标注可以沉淀为画布节点。
- 笔记节点可以继续被连接、组织、引用，并作为上下文参与 AI 对话。

## 3. Inkcode 可参考能力

Inkcode 中可作为 Zenme 阅读体系参考原型的能力包括：

- 支持 EPUB、PDF、TXT 等阅读资料。
- 支持书籍导入后解析标题、作者、封面、目录等元数据。
- 支持 EPUB/TXT 预处理分页，形成统一页面对象。
- 支持 PDF 逐页渲染。
- 支持单页阅读和滚动阅读。
- 支持左侧目录、中央阅读窗口、右侧标注/笔记列表的三栏布局。
- 支持阅读进度保存。
- 支持文本高亮、笔记、批注。
- 支持 PDF 区域标注和 OCR。
- 支持将标注或摘录升级为素材卡片。
- 支持 AI 拆书，生成结构化素材。

Zenme 实现阅读体系时，应优先复刻阅读、标注、摘录、笔记和节点引用等能力体验；Inkcode 中的独立书库、SQLite 本地数据层和写作工作台不作为 Zenme 的实现目标。

## 4. 已确认需求

### 4.1 书籍拖入画布

- 用户可以从操作系统拖动书籍文件到项目画布中。
- 支持的首批图书类型建议为 EPUB、PDF、TXT。
- 图书拖入后形成一个画布节点。
- 图书节点应区别于普通文件节点，至少在视觉或节点数据中标记为 `book` / `reading_asset` 类型。
- 图书节点视觉文案应显示为“书籍”，默认图标使用合上的书；阅读器节点视觉文案应显示为“阅读器”，图标使用打开的书。
- 图书节点图标应优先来自识别到的书籍封面；PDF 可使用首页渲染图作为封面，EPUB 优先读取包内声明的封面图，TXT 无封面时保留默认书本图标。
- 图书文件仍需上传到 Supabase Storage，并在 `project_files` 或阅读资料表中记录元数据。

### 4.2 图书节点操作入口

- 图书节点保留当前画布节点的加号连接交互。
- 用户从图书节点加号拖动并在空白处松手时，操作菜单中应出现“在阅读器中打开”。
- “在阅读器中打开”只对图书类型文件展示。
- 普通图片、非图书文件不展示该入口，或展示为不可用状态。
- 点击“在阅读器中打开”后，在当前项目画布中打开阅读器界面。

### 4.3 画布内阅读器布局

阅读器应在当前项目画布内部打开，布局结构可参考 Inkcode 阅读器，但视觉体系必须采用 Zenme 当前风格。

布局为三栏：

- 左侧：目录。
- 中间：阅读窗口。
- 右侧：笔记 / 标注。

布局要求：

- 阅读器是项目画布内的阅读工作界面，而不是跳出项目上下文的独立应用。
- 阅读器打开后，用户应仍能理解自己处于当前项目中。
- 阅读器在画布内打开时，应创建为一个 `reader` 画布节点，并通过连线关联原图书节点。
- 阅读器节点可以占据画布中的大块区域，用于承载目录、阅读窗口和笔记栏。
- 阅读器节点必须跟随画布一起平移、缩放和保存位置，不应以模态窗、全屏覆盖层或脱离 React Flow 节点系统的方式打开。
- 阅读器节点应允许用户在画布中移动位置，并允许调整节点窗口大小。
- 阅读器节点应允许收起和展开；收起时节点尺寸与图书节点保持一致，卡片中标明对应书籍名称和“阅读器”节点身份；从该阅读器连接出去的子节点和子连线应同步隐藏，展开时恢复显示。
- 图书节点到阅读器节点的连线应连接节点边缘锚点，视觉上表现为节点间连线，而不是连接到外置加号按钮。
- 画布缩放统一使用 Ctrl + 鼠标滚轮；阅读器节点内的普通滚轮只滚动阅读内容，不触发画布缩放或平移。
- 按住鼠标中键拖动始终移动画布，即使鼠标位于阅读器节点内部；阅读器内部不使用中键触发自身滚动或拖动。
- 阅读器不是独立书库页面，也不是脱离画布的新应用；关闭阅读器节点后应回到原画布状态。
- 阅读器应支持关闭后回到画布。
- 阅读器应保存阅读进度，下次打开同一本书时恢复上次位置。

### 4.4 画布节点分组

- 画布应支持多选节点后打组。
- 用户选中 2 个及以上未分组节点时，应展示浮动“打组”操作。
- 点击“打组”后，系统创建一个组框节点，将这些节点放入组框内并自动排列。
- 移动组框时，组内子节点应跟随移动。

### 4.5 视觉与交互风格

- 阅读体系的视觉风格必须延续 Zenme 当前画布风格，不照搬 Inkcode 的视觉设计。
- 阅读器、图书节点、笔记节点、目录栏、笔记栏、弹出菜单和工具按钮应采用 Zenme 的白色轻量界面、浅灰边框、细阴影、紧凑圆角和克制配色。
- 图标按钮、菜单、控件应优先复用 `components/zenme/visual-components.tsx` 中已有视觉组件；如果阅读体系出现新的重复控件，应沉淀为 Zenme 风格组件。
- 阅读器虽然参考 Inkcode 的三栏结构，但整体应像 Zenme 画布中的工作面板，而不是另一个应用嵌进来。
- 阅读窗口内部用于承载正文内容，可以保留接近书页的白色页面感，但外围导航、工具栏、目录、笔记和节点操作必须保持 Zenme 风格。

### 4.6 左侧目录

- 左侧目录展示书籍章节结构。
- EPUB 优先使用 EPUB 内置目录。
- PDF 如有书签目录，优先展示 PDF outline。
- TXT 可按章节标题规则生成目录。
- 点击目录项后，中间阅读窗口跳转到对应章节或页面。

### 4.7 中间阅读窗口

- 阅读窗口显示书籍内容。
- EPUB/TXT 可参考 Inkcode 的预处理分页方案，形成固定页面对象。
- PDF 可参考 Inkcode 的 PDF.js 渲染方案。
- EPUB 导入和打开需要优先避免阻塞画布：开发阶段拖入 EPUB 时不在主链路同步提取内嵌封面；阅读器应参考 Inkcode 的滚动模式，将 EPUB 章节预处理为固定页面对象，滚动模式按页堆叠并只渲染视口附近页面；EPUB 页面正文采用固定版心宽度，调整阅读器节点外框大小不改变正文排版宽度，只改变可视区域、滚动范围和两侧留白；后续可继续升级为章节级懒加载 API 和更精确的浏览器测量分页。
- EPUB 正文如果识别为中文内容，应对正文段落应用首行缩进两个字；非中文 EPUB 不应用中文段落缩进。
- EPUB 正文默认段落间距应设为 1.5em；以 100% 内容缩放为例，正文 16px 字号对应 24px 段后距。正文行高保持 32px。
- EPUB 和 PDF 阅读窗口需要提供内容缩放控件，支持缩小、放大和恢复 100%；内容缩放只作用于阅读内容自身，不改变画布缩放和阅读器节点外框大小。
- EPUB 和 PDF 在内容缩放为 100% 时，应使用一致的默认内容宽度基准；当前基准宽度为 600px，避免同为 100% 时两种格式视觉尺寸明显不一致。
- 阅读窗口首期只支持滚动阅读模式。
- 单页 / 翻页阅读模式不进入首期范围，可作为后续增强。
- 阅读窗口应支持文本选择。
- 用户选中文本后可以创建高亮、笔记或摘录。

### 4.8 右侧笔记

- 右侧展示当前书籍的笔记、标注和摘录。
- 笔记底层应按标注模型实现，而不是只保存一段纯文本备注。
- EPUB/TXT 一期标注至少保存 `selectedText`、`sectionIndex`、`offset`、`length`、`color`、`type`、`comment`，用于重新打开阅读器时在正文中恢复高亮。
- 用户选中文本后，应在选区附近出现 Zenme 风格的浮动标注工具条，允许选择高亮颜色并创建标注。
- 浮动标注工具条中，点击颜色即创建对应颜色的标注，不再额外展示“标注”按钮；需要补充备注时仍可使用右侧笔记栏保存。
- 创建标注后，正文高亮和右侧笔记列表应立即同步更新，二者消费同一份标注数据。
- 右侧标注栏按创建时间从旧到新展示；新标注创建后追加到列表底部，并立即滚动到底部；每条标注需要显示完整创建时间，包含年月日时分秒。
- 右侧笔记卡片中的六点拖拽手柄用于调整笔记列表顺序，不用于拖出画布节点；拖拽排序后需要保存顺序，刷新阅读器后保持用户调整后的顺序。
- 拖动六点手柄调整笔记顺序时，应在两个笔记卡片之间显示即将插入的位置，可通过撑开间距、虚线占位条和轻量过渡动画表达落点。
- PDF 阅读窗口应使用 PDF.js canvas 渲染，并按页面检测是否存在可选择文本：如果页面存在文本内容，应渲染 text layer，允许用户直接选中文字创建文本标注；如果页面没有文本内容，应视为纯图片 PDF，使用 overlay 拖拽区域创建区域标注。PDF 标注统一保存页内百分比 `rect`，重新打开或缩放阅读器后应按比例重绘到对应页面区域。
- 笔记应至少包含：
  - 原文选段。
  - 用户备注。
  - 所属书籍。
  - 所属页面或章节定位。
  - 创建时间。
- 点击笔记后，阅读窗口应跳转到原文位置。
- 笔记可编辑、删除。

### 4.8 笔记生成画布节点

- 用户可以从右侧笔记卡片内点击“创建画布节点”。
- 点击后在画布中创建一个独立画布节点。
- 笔记节点用于引用该条笔记，并参与后续画布组织。
- 新创建的笔记节点应保留与原书籍、原笔记、原位置的关联。
- 新创建的笔记节点应默认连接阅读器节点。
- 右侧笔记卡片的六点拖拽手柄只用于调整笔记列表顺序，不用于创建画布节点。

### 4.9 笔记节点与 AI 对话

- 笔记节点可以作为 Agent 对话上下文。
- 用户可以选中笔记节点，或从笔记节点加号发起 AI 操作。
- Agent 应能读取笔记节点中的原文、备注、书籍信息和定位信息。
- AI 对话可用于解释笔记、扩展思路、总结观点、转写成创作素材或生成下一步节点。

## 5. 推荐用户流程

### 5.1 图书进入项目

1. 用户进入项目画布。
2. 用户将 EPUB/PDF/TXT 文件拖入画布。
3. 系统上传原始文件到 Supabase Storage。
4. 系统创建图书节点。
5. 系统在后台解析基础元数据和目录。

### 5.2 打开阅读器

1. 用户从图书节点加号拖出连线。
2. 用户在空白处松手，打开节点操作菜单。
3. 如果该节点是图书节点，菜单展示“在阅读器中打开”。
4. 用户点击后打开画布内阅读器。

### 5.3 阅读和记录

1. 用户在左侧目录选择章节。
2. 用户在中间阅读窗口阅读内容。
3. 用户选中文本并创建笔记。
4. 笔记出现在右侧笔记列表。
5. 用户点击笔记可以回到原文位置。

### 5.4 笔记进入画布

1. 用户在右侧笔记卡片中点击“创建画布节点”。
2. 系统在阅读器节点附近创建笔记节点。
3. 系统保留笔记节点和原笔记、原书籍、阅读器节点之间的关联。

### 5.5 笔记参与 AI

1. 用户选中笔记节点或从笔记节点发起 Agent 操作。
2. Agent 面板读取该笔记节点上下文。
3. 用户与 AI 对话，生成解释、提纲、观点、创作片段或新节点。

## 6. 节点类型建议

### 6.1 图书节点

建议扩展当前 `CanvasNodeData`：

```ts
type CanvasNodeData = {
  kind: "image" | "file" | "text" | "agent" | "book" | "note" | "reader";
  title: string;
  fileId?: string;
  readingAssetId?: string;
  fileName?: string;
  fileSize?: number;
  previewUrl?: string;
  originalUrl?: string;
  mimeType?: string;
  uploadStatus?: "pending" | "uploaded" | "failed";
};
```

图书节点建议字段：

- `kind: "book"`。
- `title`：书名或文件名。
- `fileId`：关联 `project_files.id`。
- `readingAssetId`：关联阅读资料记录。
- `mimeType`：原始文件类型。
- `previewUrl`：封面图或默认图书图标。

### 6.2 笔记节点

笔记节点建议字段：

```ts
type NoteNodeData = {
  kind: "note";
  title: string;
  readingAssetId: string;
  readingNoteId: string;
  sourceBookTitle: string;
  selectedText: string;
  comment?: string;
  pageIndex?: number;
  chapterTitle?: string;
};
```

展示建议：

- 标题显示笔记摘要或章节名。
- 正文显示原文选段。
- 辅助信息显示书名和页码/章节。
- hover 或菜单中提供“回到原文”“让 Agent 处理”等操作。

## 7. 数据模型建议

Zenme 当前已有：

- `projects`
- `canvas_snapshots`
- `project_files`
- `project-assets` Storage bucket

当前云端运行态已新增 Supabase 阅读表与 Storage 路径；下列表结构保留为阅读体系建模参考，实际实现以 `supabase/migrations/20260628032000_create_reading_schema.sql` 和后续加固迁移为准。历史开发阶段曾允许通过可替换数据层使用本地 SQLite 验证主链路，但当前项目/阅读运行态已收口到 Supabase。

### 7.1 reading_assets

用于记录项目中的可阅读资料。

```sql
reading_assets
- id uuid primary key
- project_id uuid not null references projects(id) on delete cascade
- owner_id uuid not null references auth.users(id) on delete cascade
- file_id uuid not null references project_files(id) on delete cascade
- title text not null
- author text
- format text not null
- cover_path text
- toc jsonb not null default '[]'::jsonb
- page_count integer not null default 0
- preprocess_status text not null default 'pending'
- created_at timestamptz not null default now()
- updated_at timestamptz not null default now()
```

### 7.2 reading_page_cache

用于存储预处理后的页面缓存。

```sql
reading_page_cache
- id uuid primary key
- asset_id uuid not null references reading_assets(id) on delete cascade
- owner_id uuid not null references auth.users(id) on delete cascade
- page_index integer not null
- section_index integer not null default 0
- text text not null default ''
- html text
- storage_path text
- cache_version integer not null default 1
- created_at timestamptz not null default now()
- unique(asset_id, page_index, cache_version)
```

说明：

- 最终云端方案中，页面缓存优先存 Supabase 表。
- 开发阶段页面缓存可以先存本地 SQLite。
- 如果后续遇到 Supabase 行大小、性能或读取成本问题，再评估将大体积页面内容拆到 Storage。

### 7.3 reading_progress

用于保存用户阅读进度。

```sql
reading_progress
- id uuid primary key
- asset_id uuid not null references reading_assets(id) on delete cascade
- owner_id uuid not null references auth.users(id) on delete cascade
- page_index integer not null default 0
- progress_percent numeric not null default 0
- updated_at timestamptz not null default now()
- unique(asset_id, owner_id)
```

### 7.4 reading_notes

用于保存高亮、标注、笔记和摘录。

```sql
reading_notes
- id uuid primary key
- asset_id uuid not null references reading_assets(id) on delete cascade
- project_id uuid not null references projects(id) on delete cascade
- owner_id uuid not null references auth.users(id) on delete cascade
- page_index integer not null default 0
- chapter_title text
- selected_text text not null
- locator text
- color text not null default 'yellow'
- type text not null default 'highlight'
- rect jsonb
- comment text not null default ''
- created_node_id text
- created_at timestamptz not null default now()
- updated_at timestamptz not null default now()
```

说明：

- `locator` 可存 EPUB 字符偏移、PDF 页码或后续更稳定的位置表达。
- `created_node_id` 用于记录该笔记是否已经拖拽创建过画布节点。

## 8. RLS 和权限原则

- 所有阅读相关业务表必须开启 RLS。
- 所有记录必须包含 `owner_id`。
- 用户只能访问自己的 `reading_assets`、`reading_page_cache`、`reading_progress`、`reading_notes`。
- 插入和更新时需要校验 `project_id` 属于当前用户。
- 通过 `file_id` 关联文件时，需要校验对应 `project_files.owner_id = auth.uid()`。
- Storage 路径继续沿用 `{user_id}/{project_id}/...` 的隔离方式。
- 不得把 Supabase service role key、模型 API Key 等敏感信息暴露到前端。

## 9. 技术实现建议

### 9.1 Inkcode 能力定位

Inkcode 已经实现 PDF、EPUB 和 TXT 的阅读能力，足以作为 Zenme 阅读体系第一版的技术底座和能力参考。

Zenme 不需要从零验证阅读内核，但需要把这些能力重新接入 Zenme 的产品对象：

- 图书节点。
- 项目文件。
- 画布内阅读工作界面。
- 阅读笔记。
- 笔记节点。
- Agent 上下文。

因此，一期开发可以优先复用 Inkcode 中已经验证过的阅读处理思路和关键实现，但最终产品形态必须服务于 Zenme 画布体系。

### 9.2 可参考 Inkcode 实现

可优先参考并在 Zenme 架构内重新实现：

- EPUB 元数据和目录解析。
- EPUB 章节内容解析和资源路径重写。
- 页面分页引擎。
- `PageFrame`、`SinglePageView`、`ScrollView`、`PdfPageFrame` 等阅读组件。
- 高亮定位和渲染逻辑。
- PDF.js 配置。
- OCR 逻辑作为后续能力参考。

### 9.3 需要重新接入的部分

- Inkcode 的 SQLite 服务层不能直接成为 Zenme 的长期业务数据层。
- 本地文件路径读取在最终云端方案中需要改为 Storage signed URL 或服务端代理读取。
- Inkcode 的 `bookId: number` 在最终云端方案中需要改为 `assetId: uuid`。
- Inkcode 的独立 `/library` 页面不作为 Zenme 阅读体系的一部分。
- Inkcode 的 Anthropic AI 拆书接口需要改为 Zenme 当前模型接口。

### 9.4 开发期 SQLite 方案

为了尽快验证“图书节点 → 阅读 → 笔记 → 画布节点 → AI 对话”主链路，开发阶段可以先调用本地 SQLite。

开发期 SQLite 方案要求：

- 可以参考 Inkcode 的 `better-sqlite3` 表结构和读写方式。
- 可以先用本地文件路径或开发期临时文件目录处理图书文件。
- 必须建立阅读数据访问抽象，避免组件直接依赖 SQLite。
- 阅读器组件只调用统一的 repository / service / API，不关心底层是 SQLite 还是 Supabase。
- 后续切换 Supabase 时，只替换数据访问实现，不重写阅读器 UI 和画布交互。

建议抽象接口：

```ts
type ReadingRepository = {
  createReadingAsset(input: unknown): Promise<unknown>;
  getReadingAsset(assetId: string): Promise<unknown>;
  getSections(assetId: string): Promise<unknown[]>;
  getPageCache(assetId: string): Promise<unknown[]>;
  savePageCache(assetId: string, pages: unknown[]): Promise<void>;
  getProgress(assetId: string): Promise<unknown>;
  saveProgress(
    assetId: string,
    pageIndex: number,
    progressPercent: number,
  ): Promise<void>;
  listNotes(assetId: string): Promise<unknown[]>;
  createNote(input: unknown): Promise<unknown>;
  updateNote(noteId: string, input: unknown): Promise<unknown>;
  deleteNote(noteId: string): Promise<void>;
};
```

开发期实现：

- `sqliteReadingRepository`

最终云端实现：

- `supabaseReadingRepository`

### 9.5 推荐阶段

第一阶段：

- 图书拖入画布并识别为图书节点。
- 只通过图书节点加号菜单展示“在阅读器中打开”，图书节点双击不打开阅读器。
- 从图书节点加号拖动并选择“在阅读器中打开”时，需要创建一条连线。
- 画布内打开三栏阅读工作界面。
- 基于 Inkcode 已有能力，优先打通 EPUB、PDF、TXT 阅读入口中的可复用部分。
- 阅读器首期只支持滚动模式。
- 支持基础笔记。
- 支持从笔记卡片按钮生成画布节点；同一条笔记允许创建多个画布节点。
- 笔记节点创建后，右侧笔记列表不需要显示“已生成节点”状态。
- 笔记节点与原图书节点默认自动连线。
- 笔记节点允许继续通过节点加号创建新节点。
- 支持单个笔记节点进入 Agent 上下文。
- AI 拆书不进入首期范围，首期先做阅读功能。
- 未登录用户访问阅读相关 API 时需要登录；当前阅读数据不再使用未登录本地演示模式。
- 当前阅读 repository 已切换到 Supabase，旧 SQLite repository 不再作为运行态实现。

第二阶段：

- 完善 EPUB/PDF/TXT 三种格式。
- 增加页面缓存。
- 增加阅读进度恢复。
- 增加目录跳转。
- 增加高亮和笔记编辑删除。
- 支持单页 / 翻页阅读模式。
- 支持多个笔记节点批量作为 Agent 上下文。

第三阶段：

- 增加 PDF 区域标注和 OCR。
- 增加 AI 拆书。
- 将 AI 拆书结果生成画布节点或节点组。
- 支持多个笔记节点批量汇总、比较和生成结构。

## 10. 产品决策

- 阅读能力应嵌入项目画布，而不是成为独立书库。
- 阅读体系的视觉设计必须采用 Zenme 当前风格；Inkcode 只作为能力和布局结构参考，不作为视觉参考。
- 阅读器应在画布内作为阅读工作界面打开，关闭后回到原画布状态。
- Inkcode 的 PDF、EPUB、TXT 阅读能力足以支撑第一版阅读内核，但需要在 Zenme 中重新接入画布节点、笔记节点和 Agent 上下文。
- 历史开发阶段曾允许先使用本地 SQLite 加速验证；当前运行态已切换到 Supabase，SQLite 不再作为阅读体系的业务数据层。
- 图书资料首先是画布节点，其次才是阅读器入口。
- 图书节点不通过双击打开阅读器；首期只通过节点加号菜单中的“在阅读器中打开”进入阅读界面。
- 从图书节点加号拖动并选择“在阅读器中打开”时，需要创建连线。
- 阅读器首期只支持滚动模式。
- 笔记不是阅读器内部的孤立数据，应能转化为画布节点。
- 笔记节点应保留来源关系，便于回到原文和参与 AI 上下文。
- 同一条笔记允许拖拽创建多个画布节点。
- 笔记节点创建后，右侧笔记列表不需要显示“已生成节点”状态。
- 笔记节点与图书节点默认自动连线。
- 笔记节点允许继续通过节点加号创建新节点。
- Agent 首期只引用单个笔记节点作为上下文。
- AI 拆书不进入首期范围，首期先完成阅读功能和笔记节点链路。
- 页面缓存如后续进入运行态，优先采用 Supabase 表或 Storage 方案。
- 未登录本地演示模式不再作为当前阅读体系运行策略；未登录访问走登录流程。
- 首期不实现 Inkcode 的完整写作工作台。
- 首期不要求把所有 Inkcode 阅读功能一次性实现，应先打通“图书节点 → 阅读 → 笔记 → 画布节点 → AI 对话”的主链路。
